# RAG 长答案生成实战：报告式回答怎么工程化

大部分 RAG 教程都假设「用户问一句，模型答一段」。但真实需求里有一大类是**长答案**：写一篇调研报告、出一份方案对比、生成一份带结构的分析文档。这种「报告式回答」和「一句话问答」在工程上完全是两码事——它涉及长上下文管理、分步生成、篇幅控制、以及「写长了不跑偏」。

本文讲清楚：长答案生成有哪些特有难题、三种生成策略怎么选、以及怎么让模型「写长但不写歪」。

## 一、长答案的特有难题

短问答的痛点（幻觉、答非所问）长答案全都有，还额外多几个：

- **上下文装不下**：报告要引用十几篇文档，全塞进一个 prompt 直接超长，模型后半段开始忘前半段。
- **结构易崩**：写长了容易逻辑跳跃、前后重复、小节编号乱掉。
- **篇幅失控**：要么写两行就停（没展开），要么写到上万字（废话连篇）。
- **中途跑偏**：生成到第 5 段突然开始编文档里没有的内容。
- **生成中断**：超长输出可能触发模型的 max_tokens 截断，报告戛然而止。

## 二、策略一：大纲驱动（推荐）

把长答案拆成「先出大纲 → 逐节展开 → 拼装」三步，是最稳的做法。

```
1. 大纲阶段：把所有召回文档 + 用户需求喂给模型，让它先输出结构化大纲
   → 输出：一、背景 二、对比 三、选型建议 ...（各节一句说明）
2. 逐节阶段：拿着完整文档，针对每一节单独生成内容
   → 每节一个独立 prompt，上下文短、可控、不易跑偏
3. 拼装阶段：把各节拼起来，再过一遍「统稿」模型做衔接和去重
```

优点：每节上下文短， hallucination 风险低；大纲先行保证结构不崩；某节写砸了只重生成那一节。缺点：调用次数多（大纲 1 + 每节 1 + 统稿 1），成本和延迟高。

适合：报告、方案、对比分析这类「结构比文采重要」的场景。

## 三、策略二：检索增强的长生成

如果必须一次生成（不想多次调用），可以用「生成一段 → 检索补充一段」的交错方式：

```
模型生成第 1 段
→ 用第 1 段里的关键问点，再检索补充文档
→ 模型基于补充文档生成第 2 段
→ 循环
```

本质上是把「一次性长生成」变成「边写边查」。适合叙述类长文，但实现复杂，且要防循环检索。

## 四、策略三：Map-Reduce（超长文档汇总）

当源材料本身极长（比如上百页 PDF 要出摘要），连「逐节展开」都装不下时，用 Map-Reduce：

```
Map：把文档切成 N 块，每块独立生成「局部摘要」
Reduce：把所有局部摘要再汇总成「全局摘要」
```

这是处理超长源材料的经典法子，后面有专门一篇讲，这里不展开。

## 五、让长生成「不跑偏」的几个硬手段

1. **每节强制引用**：要求每节答案标注 `[1][2]`，生成后校验「引用编号是否都在传入文档范围内」。出现文档外的编号 = 幻觉，自动重生成该节。
2. **大纲即契约**：逐节生成时，把「大纲 + 当前小节标题 + 该节要点」写进 prompt，约束模型只写这一节，不要提前写后面的、不要重复前面的。
3. **篇幅硬约束**：prompt 里明确「本节 300~500 字」，并监控实际输出，严重偏离就重生成。比「请写详细点」这种软指令靠谱。
4. **max_tokens 留余量 + 续写**：长生成设足够大的 max_tokens，并对「因截断中断」做检测——如果输出在句子中间结束，自动 append「继续」让模型续写。
5. **统稿去重**：多节拼装后，过一遍统稿模型，专门处理「前后重复、衔接生硬、编号冲突」，这一步能显著提升可读性。

## 六、流式输出体验

长答案生成慢（可能十几秒到几十秒），**必须流式输出**，否则用户以为卡死了。工程上：

- 边生成边把 token 推给前端（SSE / 流式 API）；
- 先快速返回一个「大纲骨架」占住界面，再逐步填充各节；
- 在界面上标注「正在生成第 X 节」，给用户预期。

体验上，「慢但看得见进展」远好于「快但黑屏三秒后一次性吐出」。

## 七、评测长答案

长答案不能只看「对不对」，还要看「结构好不好、全不全」：

- **覆盖率**：用户需求里的要点，答案是否都覆盖（用要点 checklist 比对）；
- **结构分**：小节划分是否合理、有无重复 / 缺失；
- **忠实度**：长文里幻觉更难发现，建议分段做 Faithfulness 检查；
- **可读性**：篇幅是否适中、衔接是否自然（可人工抽样）。

## 小结

长答案生成是 RAG 从「问答玩具」走向「生产工具」的关键一步。核心思路是**不要试图一次生成完美长文**，而是用「大纲驱动 + 逐节展开 + 统稿」把大任务拆小：每节上下文短、可控、易校验，整体结构靠大纲锁死。再配合流式输出和分段忠实度检查，就能稳定产出「长而不歪」的报告式答案。
