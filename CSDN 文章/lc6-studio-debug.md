# 可视化调试：LangGraph Studio 与检查点回看

写 Agent 最头疼的是「它到底哪一步出了问题」。LangGraph 的检查点机制天然给了一套**可视化调试**能力：本地用 **LangGraph Studio**，云端用 **LangSmith**，都能把图的执行轨迹画出来。这里重点讲本地 Studio + 检查点回看。

## 一、LangGraph Studio 是什么

Studio 是一个本地可视化工具（通过 `langgraph-cli dev` 启动），把你的图以交互方式呈现：节点、边、运行状态一目了然。你可以：
- 在界面上直接输入，触发图运行；
- 实时看到每个节点的输入输出；
- 点开任意节点，查看当时的完整状态。

启动方式（需先装 `langgraph-cli`）：

```bash
langgraph dev
```

它会读取项目里的 `langgraph.json`（声明入口图），打开浏览器即可操作。

## 二、配合检查点回看

因为每次运行都有检查点，Studio 能列出某条 thread 的全部历史，并让你：
- **逐检查点查看**：点开某一步，看那时状态长什么样；
- **时间旅行**：在界面上改一个值、从某步重放（对应代码里的 `update_state`，见「时间旅行」篇）；
- **断点调试**：在 Studio 里给节点设断点，运行到那一步停下，检查后再放行。

这把「改代码→重跑→看日志」的循环，变成了「在界面上点一点」的可视化操作。

## 三、什么时候用 LangSmith

Studio 偏本地开发；**LangSmith** 偏生产可观测：
- 记录线上每一次运行的完整 trace；
- 按延迟、错误率、token 成本筛选；
- 做评测数据集、跑回归。

两者共享同一套检查点/状态模型，本地复现的问题，到了线上也能用 LangSmith 对上。

## 四、调试心法

- 不确定某节点输出了什么 → Studio 点开看，比 print 强十倍；
- 某步答错了 → 用时间旅行改那步重放，不用从头跑；
- 线上异常 → LangSmith 拉 trace，定位是哪个工具/哪个模型调用出的问题。

一句话：LangGraph 的「图 + 检查点」不只是运行时结构，也是调试界面背后的数据源。把 Studio/LangSmith 用起来，Agent 调试从瞎猜变成可观测的工程。
