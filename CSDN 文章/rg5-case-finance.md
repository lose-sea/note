# 金融 RAG 落地案例实战：一个知识库从 0 到 1 的真实路径

前面讲了那么多 RAG 的组件和技术点，这一篇把它们串起来——以一个**金融机构内部研报 / 合规知识库问答**为原型，走一遍从需求到上线的完整路径。金融场景对「准确、可追溯、合规」的要求极高，正好能检验前面所有技术的成色。

## 一、需求画像与约束

场景：券商研究员 / 客户经理，想快速从海量历史研报、产品说明书、合规条款里找到答案，而不是人工翻档案。

硬约束（金融特有）：

- **零幻觉容忍**：给错的投资建议或合规结论，后果严重，必须句句有出处。
- **强合规**：数据不能出内网，必须私有化部署（对应本地栈专篇）。
- **可追溯**：每个答案必须能点回原文研报，审计要能查。
- **时效性**：产品收益率、政策条款会变，答案必须标注时间（对应时效性专篇）。

这四条直接决定了技术选型。

## 二、技术选型（对照前面的专篇）

| 需求 | 选型 | 对应技术 |
|------|------|----------|
| 数据不出网 | 全本地栈 | bge-m3 + Qwen 本地 + Qdrant |
| 句句有据 | 引用溯源 + 约束生成 | 强制 `[1][2]` 标注 + 逐句校验 |
| 可追溯 | 引用系统 | 文档 id 关联 + 前端可点击 |
| 时效正确 | 时间标签 | 文档打 `effective_date` + 过期提示 |
| 成本可控 | 成本优化 | 检索缓存 + rerank 精选 |
| 格式规范 | 提示词模板 + few-shot | 研报式答案模板 + 示例 |

可以看到，前面每一篇技术在这里都有用武之地——这不是堆砌，是被需求逼出来的。

## 三、数据入桶流程

金融文档类型杂：PDF 研报（带图表）、Word 产品说明书、Excel 数据表、网页公告。流程：

```
1. 解析：PDF 用版面感知解析（Docling），表格用结构化抽取，
   保证研报表格、数据不被破坏（对应文档解析专篇）
2. 切片：研报按「章节 + 图表」切块，表格整块保留，避免数字被切碎
3. Embedding：bge-m3 本地向量化，query 加检索前缀
4. 元数据：每片打 来源研报名 / 发布日期 / 产品 / 合规等级 标签
5. 入 Qdrant：向量 + 元数据一起存，支持按产品/日期过滤
```

## 四、检索与生成链路

```
用户问："XX 产品当前费率和管理费怎么算？"
  → query 改写补全（多轮场景）
  → bge-m3 embedding + Qdrant 向量检索 top-20
  → rerank 精选 top-5（按产品/日期过滤后）
  → 拼 prompt（研报模板 + 强制引用 + 时间提示）
  → 本地 Qwen 生成，逐句标 [1][2]
  → 输出：答案 + 可点击引用 + "信息截至文档日期" 提示
```

这里几个金融特色处理：

- **产品 / 日期过滤**：检索时 `where={"product":"XX","date>=最新"}`，保证不召回已停产产品的旧条款。
- **费率数字精确**：涉及费率计算，走「表格抽取 + 程序校验」（对应数字问答专篇），不让模型心算。
- **合规免责声明**：答案末尾自动附加「本回答基于历史研报，不构成投资建议」，合规硬性要求。

## 五、上线后的关键运营

- **反馈闭环**：用户对答案点「有用 / 无用」，积累评测集，定期回归 Faithfulness。
- **人工抽检**：合规岗定期抽看答案，确认引用准确、无幻觉。
- **知识库更新**：新研报 / 新政策进来走增量索引，旧条款标 `superseded_by` 自动降权。
- **成本看板**：监控单问答成本，缓存命中率，避免账单失控。

## 六、踩过的坑（真实经验）

- **研报表格切碎导致数字问答全错**：早期按固定长度切，表格被腰斩，费率算不出。改成「表格整块 + 章节语义块」后解决。
- **旧产品条款被召回**：没打产品生效日期，用户问当前费率却召回了已下架产品的旧费率。加时间过滤后解决。
- **模型编造研报编号**：早期没强制引用，模型编了不存在的 `[3]`。加「引用编号必须落在传入文档范围」的校验后解决。
- **合规免责漏加**：某次模板更新把免责声明删了，被审计发现。把免责声明做成不可移除的「固定后缀」。

## 七、成效

落地后，研究员查一份历史研报平均从 15 分钟降到 30 秒；合规条款问答的「有据率」（答案每句能溯源）从人工抽查的 70% 提升到 98%；全程数据零出网，通过合规审计。

## 小结

这个金融案例本质上是前面所有 RAG 技术的「综合考试」：本地栈解决合规、引用 + 约束生成解决幻觉、时间标签解决时效、检索缓存解决成本、表格抽取解决数字。它的价值不在于用了多炫的技术，而在于**每个技术点都被一个真实约束逼出来、且都派上了用场**。如果你正要落地一个 RAG 项目，照着「列约束 → 选技术 → 串链路 → 运营 + 评测」这条路走，能少踩大半坑。
