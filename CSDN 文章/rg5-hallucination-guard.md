# 引用约束生成实战：让模型句句有据，把幻觉率再压一个量级

上一篇解决了"答案能不能点回原文"，这一篇解决更狠的问题：**怎么让答案里的每句话都有出处，没出处的宁可不说**。基础 RAG 的生成 prompt（"基于以下资料回答问题"）约束非常软——资料不全时模型会"热心"地用训练知识补全，语气自信，事实全错。引用约束生成（constrained generation）就是给模型套上笼头：**逐句标注来源、无据即拒答、生成后逐句核对**。这篇文章讲三层约束的设计、拒答率的平衡艺术、以及 faithfulness 的度量。

## 一、为什么"基于资料回答"这句话约束不住模型

先看一个实验。给模型一段不完整的资料，问资料里没有的问题：

```
【资料】
[1] 违约金比例：合同总额的 5%。
[2] 争议解决地：上海仲裁委员会。

【问题】
违约金的支付期限是多久？

【弱约束 prompt（常见写法）】
"请基于以上资料回答用户问题。"
→ 模型输出："违约金应在违约行为发生后 30 日内支付。"（资料里根本没有！
  这是编的，但用户以为有据）
```

**LLM 的本质是"续写最合理的文本"，不是"核查事实的数据库查询器"**。资料不全时，它默认该用"合理知识"补全——礼貌、流畅、错误。弱约束 prompt 改变不了这个行为模式。

强约束要做的是三件事：**让"引用"变成格式义务**（每句话必须挂来源）、**让"无据"变成合法输出**（明说没资料，不丢人）、**让"核对"变成生成后的程序**（不信模型自评）。

## 二、第一层约束：格式义务——逐句标注

约束 prompt 的严格版：

```
【回答格式（必须严格遵守）】
1. 你的回答只能由"论断句 + [来源编号]"组成
2. 每个论断句末尾必须紧跟来源编号，如：违约金比例为合同总额的 5%[1]
3. 一句话只能引用一段资料；综合多段的论断拆成多句分别标注
4. 找不到资料支持的论断，禁止输出该句
5. 允许输出："根据现有资料，无法确定违约金的支付期限。"

【资料】
[1] 违约金比例：合同总额的 5%。
[2] 争议解决地：上海仲裁委员会。
```

关键在第 1、3、4 条：**"只能由论断句+编号组成"是格式宪法**——不允许模型自由发挥寒暄、总结、延伸。第 3 条防止"一句话挂三个引用"的模糊归属（"[1][2][3] 都对"到底是哪句支持哪个论断？）。第 4 条是废话删除条款：没有支撑的句子，输出本身就是违规。

**结构化输出兜底**：用 JSON mode / function calling 把格式钉死，比自然语言约束可靠一个量级：

```python
from pydantic import BaseModel

class CitedAnswer(BaseModel):
    sentences: list[Sentence]      # 每句强制带 cite_ids
class Sentence(BaseModel):
    text: str
    cite_ids: list[int]            # 至少 1 个，且 ≤ 编号总数
    confidence: float              # 可选：模型自评支撑强度
```

JSON schema 强制 `cite_ids` 非空——**格式层面消灭"无引用句子"**，比 prompt 里求它管用。

## 三、第二层约束：无据即拒答——拒答率平衡术

强约束的副作用：模型变"胆小"，能答的也说不知道。护数据纯洁性和用户体验之间的平衡，是这套系统的真实调优点。

### 3.1 三档响应策略

```
检索结果质量 → 响应档位：

档 1 强支撑（Top chunk 相关度 > 0.8 且覆盖问题要点）
  → 正常生成，逐句引用

档 2 弱支撑（Top chunk 相关度 > 0.5，或要点部分覆盖）
  → 生成"资料表明……但以下方面资料未覆盖：X、Y"
  → 允许基于资料的部分回答 + 明确缺口声明

档 3 无支撑（Top chunk 相关度 < 0.3）
  → 直接拒答："现有知识库中未找到相关信息，建议联系 XX / 换个问法"
  → 拒答时给出"建议换个什么问法"（从 query 理解层拿线索）
```

### 3.2 档 3 的工程价值：拒答要拒得有用

纯"我不知道"是负体验。好的拒答 = 道歉 + 归因 + 出路：

```
"知识库里没有关于'离职证明开具流程'的文档（检索最相关的
是《入职指南》相关度仅 0.2）。

你可以：
1. 换个说法试试，比如'离职手续怎么办'
2. 联系 HR 咨询
3. 查看知识库中没有的相关分类：入职 / 考勤 / 薪酬"
```

第三条从检索日志的"同类已解决问题"里捞建议问法——**拒答变成导航，不是死胡同**。

### 3.3 拒答率监控：这个指标必须单列

拒答率 = 拒答次数 / 总查询。两条红线：

- **拒答率飙升**（比如从 5% 到 30%）：要么检索侧出了问题（索引挂了/过滤过度），要么 prompt 约束太紧把能答的也拒了——先查检索质量再看 prompt；
- **拒答率归零**：模型在"不懂装懂"，约束失效——查 prompt 有没有被改坏，或模型换了不遵守格式的版本。

健康的拒答率在 10%~25%（视业务而定，客服库可以更低，合规库必须更高），**把它做成仪表盘和告警项，和准确率同级监控**。

## 四、第三层约束：生成后逐句核对

模型自评的引用不可全信，程序化核对是最后一关。核对两个层次：

### 4.1 引用有效性（轻量，全量跑）

上一篇讲的：每个 cite_id 在 context 里存在、每句至少一个引用。**轻到可以每次生成都跑**，正则 + 集合运算的事。

### 4.2 支撑关系核对（重量，抽样跑）

"这句话的内容真的出自被引的那段吗"——需要语义比对。两种实现：

**规则版（便宜）**：论断句的实体/数字/关键词必须在被引 chunk 里出现。问"违约金 5%[1]"，chunk 里必须同时有"违约金""5%"。数字和专有名词的规则匹配准确率其实很高：

```python
def check_support(sentence, cited_chunk):
    nums = set(re.findall(r"\d+\.?\d*%?", sentence.text))
    if nums and not nums <= set(re.findall(r"\d+\.?\d*%?", cited_chunk)):
        return False                    # 论断里的数字被引段没有 = 疑似编造
    # 实体词/专名粗查（用 jieba 分词或预训练 NER）
    terms = extract_key_terms(sentence.text)
    hit = sum(t in cited_chunk for t in terms) / len(terms)
    return hit >= 0.6
```

**模型版（准但贵）**：小模型当裁判，输入"论断 + 被引 chunk"，输出"支持/不支持/部分支持"。离线批处理跑，不占实时链路。

**处理策略**：核对不通过的句子，从答案里剔除，并在答案末尾声明"部分内容因无法核实来源已隐去"——**宁可答案短，不可答案假**。

## 五、faithfulness 度量：怎么量化"有据程度"

约束生成的效果要靠 faithful 指标度量，公式：

```
faithfulness = 被资料支持的句子数 / 答案总句数
```

计算方式：离线评估集上，人工或裁判模型对每句标注"资料支持/资料无关/资料矛盾"，汇总成三个比例：

| 指标 | 含义 | 目标 |
|---|---|---|
| **faithfulness** | 有据句占比 | > 0.9 |
| **contradiction_rate** | 和资料矛盾的句占比 | < 0.02 |
| **answer_relevance** | 答案实际回应了问题 | > 0.85（防"过度保守"） |

**三个指标必须一起看**：只追 faithfulness 会把模型逼成"复读机"（答案全是资料原句拼贴，faithfulness 100% 但没用）；只追 relevance 回到老路上（啥都敢答）。**faithfulness × relevance 双高，才是约束生成的成功。**

RAGAS 框架里有标准实现（faithfulness + answer relevance + context precision/recall 四件套），评估集从真实查询日志构造 + 人工标注一千条是初期投入，之后增量维护。

## 六、和检索质量的联动：约束生成的输入端

约束生成改的是"输出端"，但幻觉的一大概率根源在"输入端"——**检索回来的东西本来就是错的，生成端再约束也是垃圾进垃圾出**。联动监控：

- 检索层：context precision（召回的 chunk 里多少真相关）低 → 先生成端拿不到好料，faithfulness 上不去；
- 组合指标算"端到端 faithfulness"和"检索层 precision"两条曲线，定位瓶颈在哪一层；
- 经验分布：**约束生成能把检索精度的上限提高 15~20%，但检索精度低于 60% 时，生成端也救不回来**——那时候该修索引而不是修 prompt。

## 七、落地检查清单

- [ ] 强约束 prompt 三段式：格式宪法（论断句+引用）、无据拒答条款、资料边界声明；
- [ ] JSON mode / function calling 强制 cite_ids 非空；
- [ ] 三档响应策略（强支撑/弱支撑+缺口声明/拒答+建议问法）；
- [ ] 拒答率单列监控，红线双向告警（飙升 = 检索坏 or 过紧；归零 = 约束失效）；
- [ ] 生成后两层核对：引用有效性全量、支撑关系抽样 + 高风险场景全量；
- [ ] 不通过句子剔除 + 声明，宁可短不可假；
- [ ] faithfulness / contradiction / relevance 三指标评估集 + RAGAS 对接；
- [ ] 端到端指标和检索 precision 分层看，瓶颈定位到层。

## 八、小结

引用约束生成的四句话：

- **LLM 默认补全而非核查**，"基于资料回答"是弱约束，改变不了行为模式——必须格式义务、拒答合法化、程序化核对三管齐下；
- **格式是宪法不是建议**：JSON schema 强制每句带 cite_ids，比 prompt 请求管用一个量级；
- **拒答率是平衡艺术**：纯"我不知道"是负体验，好的拒答 = 道歉 + 归因 + 建议问法 + 相关分类导航；拒答率要和准确率同级监控，双向红线；
- **faithfulness 三指标一起考核**：有据率 × 相关率双高才算成，只追一个指标都会被模型钻空子——复读机和瞎编是两个极端，都要防。
