为你的天气预报项目添加数据持久化，让收藏的城市在应用重启后依然保留，是一个合理的增强功能。当前项目已具备良好的 Model（`CityModel`）和单例（`HomeModel`），扩展起来非常方便。下面给出具体方案，**不直接修改代码**，只提供实现思路和注意事项。

------

## 一、选择持久化方案

针对你当前的技术栈（Objective-C + UIKit），有以下几种方案：

| 方案                           | 优点                                    | 缺点                                                         | 适用场景                                       |
| :----------------------------- | :-------------------------------------- | :----------------------------------------------------------- | :--------------------------------------------- |
| **NSUserDefaults**             | 简单，无需额外文件管理，适合小数据      | 不适合存储大量数据，但收藏城市数量通常很少（< 100 个），完全够用 | 推荐，简单高效                                 |
| **NSCoding + 归档（Archive）** | 可存储自定义对象，支持复杂结构          | 需要实现 `encodeWithCoder:` 和 `initWithCoder:`，代码稍多    | 若想直接序列化整个 `CityModel` 数组，可选用    |
| **Property List（plist）**     | 可读性好，适合存储 NSArray/NSDictionary | 需要手动转换为 plist 兼容类型（`NSString`, `NSNumber`, `NSArray`, `NSDictionary`） | 与 NSUserDefaults 类似，但更明确地控制文件位置 |
| **Core Data**                  | 强大的对象图管理、查询能力              | 过重，对简单收藏功能不必要                                   | 不推荐，过度设计                               |

**推荐使用 `NSUserDefaults`**，因为：

+ 收藏城市数量一般很少（< 50 个），性能无影响。
+ 存取接口简洁，`[[NSUserDefaults standardUserDefaults] setObject:forKey:]` 和 `objectForKey:`。
+ 可以存储 `NSArray` 或 `NSDictionary`，只需把 `CityModel` 转换为字典。

------

## 二、保存的数据结构

`CityModel` 有三个关键属性：`cityName`（字符串）、`latitude`（浮点数）、`longitude`（浮点数）、`cityID`（字符串，可由经纬度生成）。我们只需保存这些即可恢复对象。

建议以 **字典数组** 的形式保存：

objc

```
NSArray *savedCities = @[
    @{@"name": @"西安 -- 陕西", @"lat": @34.25833, @"lon": @108.92861},
    @{@"name": @"北京 -- 北京市", @"lat": @39.90750, @"lon": @116.39723},
    // ...
];
```



`cityID` 可在恢复时根据经纬度重新生成，所以不必额外存储。

------

## 三、保存时机

+ 当用户 **添加城市**（`WeatherController` 的 `pressAdd` 方法成功执行）时，立即保存。
+ 当用户 **删除城市**（`HomeController` 的 `commitEditingStyle:` 或清空收藏）时，立即保存。
+ 当应用进入 **后台** 或 **终止** 时，也可以主动保存（可选，作为额外保险）。

因为 `HomeModel` 是单例，持有 `homeCities` 数组，我们可以在 `HomeModel` 中添加一个 `save` 方法，负责将 `homeCities` 序列化为字典数组，存入 `NSUserDefaults`。

------

## 四、恢复时机

应用启动时（`SceneDelegate` 的 `willConnectToSession:` 或 `HomeController` 的 `viewDidLoad`），应先尝试从 `NSUserDefaults` 读取数据。如果存在，则用其构建 `CityModel` 数组并赋值给 `homeCities`；如果不存在，则使用默认的硬编码城市（如你现在所做的）。

这样，用户首次启动看到默认城市，之后添加/删除都会持久化。

------

## 五、实现步骤概述

### 1. 在 `CityModel` 中添加转换方法

为了便于序列化，给 `CityModel` 增加两个方法：

objc

```
- (NSDictionary *)dictionaryRepresentation;
+ (instancetype)modelWithDictionary:(NSDictionary *)dict;
```



前者返回 `@{@"name": self.cityName, @"lat": @(self.latitude), @"lon": @(self.longitude)}`，后者从字典创建实例。

### 2. 在 `HomeModel` 中实现保存和加载

objc

```
- (void)saveToUserDefaults {
    NSMutableArray *array = [NSMutableArray array];
    for (CityModel *city in self.homeCities) {
        [array addObject:[city dictionaryRepresentation]];
    }
    [[NSUserDefaults standardUserDefaults] setObject:array forKey:@"SavedCities"];
    [[NSUserDefaults standardUserDefaults] synchronize]; // iOS 12+ 可省略
}

- (void)loadFromUserDefaults {
    NSArray *saved = [[NSUserDefaults standardUserDefaults] objectForKey:@"SavedCities"];
    if (saved && saved.count > 0) {
        NSMutableArray *cities = [NSMutableArray array];
        for (NSDictionary *dict in saved) {
            CityModel *city = [CityModel modelWithDictionary:dict];
            if (city) [cities addObject:city];
        }
        self.homeCities = cities;
    } else {
        // 没有保存数据，则使用默认硬编码城市
        [self setupDefaultCities];
    }
}
```



### 3. 修改初始化逻辑

在 `HomeModel` 的 `setUpData` 中（或单例初始化时），调用 `[self loadFromUserDefaults]` 而非直接硬编码。

若没有持久化数据，则执行默认加载；若存在，则覆盖。

### 4. 在添加/删除后调用保存

在 `WeatherController` 的 `pressAdd`（添加成功后）调用 `[[HomeModel shareInstance] saveToUserDefaults]`。
在 `HomeController` 的删除方法（`commitEditingStyle:` 和 `clearAction`）中，修改 `homeCities` 后也调用 `saveToUserDefaults`。

------

## 六、注意事项

+ **线程安全**：`NSUserDefaults` 是线程安全的，但为了 UI 一致性，建议在主线程调用保存（添加/删除操作本身就在主线程）。
+ **数据一致性**：删除时务必将 `dicts`（天气数据缓存）也一起清理，否则 `dicts` 与 `homeCities` 长度不匹配，可能引起数组越界。你当前在删除时已经同步移除了 `dicts`，这一点正确。
+ **默认城市与持久化冲突**：如果持久化数据存在，则完全采用持久化数据，不再使用硬编码默认城市。这意味着用户第一次启动后看到的默认城市也会被保存，之后添加/删除都会更新保存。
+ **`cityID` 恢复**：你的 `CityModel` 的 `initWithName:Latitude:Longitude:` 内部会调用 `[self setUpCityID]`，所以从字典恢复时，只需调用该初始化方法即可自动生成 `cityID`。
+ **错误处理**：加载时若字典缺失某个键，应跳过该对象或使用默认值，避免崩溃。

------

## 七、扩展考虑（P2 建议）

+ **迁移旧数据**：如果之前版本没有持久化，首次启动会使用默认城市。之后保存时会覆盖默认，所以无需迁移。
+ **应用启动时加载**：你已在 `HomeController` 的 `viewDidLoad` 中调用 `[self setUpData]`，而 `setUpData` 内部获取 `[HomeModel shareInstance]`，因此只需在 `HomeModel` 初始化时完成加载即可。
+ **保存触发时机**：除了添加/删除，还可以在 `applicationDidEnterBackground` 中调用 `save`，确保即使应用被强杀也能保留最新数据（但非必需）。
+ **避免保存敏感信息**：你保存的只是城市名称和坐标，不涉及 API Key 或用户隐私，安全。

## 八、最小可执行代码示例（仅示意，不直接改你项目）

objc

```
// HomeModel.m
- (void)setupData {
    // 尝试加载
    NSArray *saved = [[NSUserDefaults standardUserDefaults] objectForKey:@"SavedCities"];
    if (saved && saved.count > 0) {
        NSMutableArray *cities = [NSMutableArray array];
        for (NSDictionary *dict in saved) {
            CityModel *city = [[CityModel alloc] initWithName:dict[@"name"]
                                                    Latitude:dict[@"lat"]
                                                   Longitude:dict[@"lon"]];
            [cities addObject:city];
        }
        self.homeCities = cities;
    } else {
        // 默认城市
        self.homeCities = [NSMutableArray arrayWithArray:@[ /* 默认城市们 */ ]];
    }
    self.dicts = [NSMutableArray arrayWithCapacity:self.homeCities.count];
    for (NSInteger i = 0; i < self.homeCities.count; i++) {
        [self.dicts addObject:@{}];
    }
}

- (void)save {
    NSMutableArray *array = [NSMutableArray array];
    for (CityModel *city in self.homeCities) {
        [array addObject:@{@"name": city.cityName, @"lat": @(city.latitude), @"lon": @(city.longitude)}];
    }
    [[NSUserDefaults standardUserDefaults] setObject:array forKey:@"SavedCities"];
    [[NSUserDefaults standardUserDefaults] synchronize];
}
```



在 `WeatherController` 添加成功和 `HomeController` 删除成功后，调用 `[[HomeModel shareInstance] save];`。
