# 03 - `NSUserDefaults` 底层原理与进阶特性

掌握了基本用法后，这一篇带你看看 `NSUserDefaults` 背后到底是怎么工作的，以及几个进阶开发中常用的特性。

---

## 一、数据到底存在手机的哪里？

每个 iOS App 都有自己独立的沙盒目录（Sandbox），`NSUserDefaults` 的数据最终保存在：

```text
<App沙盒根目录>/Library/Preferences/<你的BundleID>.plist
```

例如你的 App Bundle ID 是 `com.example.WeatherApp`，那么文件名就是 `com.example.WeatherApp.plist`。

### 如何在 Mac 上查看模拟器里的这个 plist 文件？

在代码中打印一下沙盒路径：
```objc
NSString *libraryPath = NSSearchPathForDirectoriesInDomains(NSLibraryDirectory, NSUserDomainMask, YES).firstObject;
NSString *prefsPath = [libraryPath stringByAppendingPathComponent:@"Preferences"];
NSLog(@"Preferences 路径: %@", prefsPath);
```
复制控制台输出的路径，在 Mac 的访达（Finder）里按 `Command + Shift + G`，粘贴路径回车，就能直接看到这个 `.plist` 文件，双击用 Xcode 打开就可以直观地看到你存进去的所有键值对！

## 二、底层读写机制：为什么它很快？

你可能会疑惑：每次调用 `objectForKey:` 都要去读硬盘文件吗？那岂不是很慢？

**不是的！** `NSUserDefaults` 采用了 **内存缓存 + 后台守护进程异步落盘** 的架构：

1. **首次加载（冷启动）**：当你第一次访问 `NSUserDefaults` 时，系统会把整个 `.plist` 文件的内容一次性加载到**内存**中缓存起来。
   - 这也是为什么**绝对不能往里面存大数据**——一旦 plist 文件很大（比如几 MB），每次启动 App 加载它就会明显拖慢启动速度并占用内存！
2. **读取操作**：直接从内存缓存里查字典，所以速度极快（微秒级）。
3. **写入操作**：先更新内存缓存，然后通过 IPC（进程间通信）通知系统守护进程 **`cfprefsd`**，由 `cfprefsd` 在合适的时机批量异步写入磁盘。
   - 因为由独立的系统进程 `cfprefsd` 负责写盘，所以哪怕你的 App 在调用完 `setObject:forKey:` 的下一毫秒就崩溃了，数据大概率也不会丢。

## 三、搜索域（Domains）机制：理解 `registerDefaults:` 的原理

当你调用 `[defaults objectForKey:@"fontSize"]` 时，`NSUserDefaults` 并不是只查一个地方，而是按**优先级从高到低**依次搜索 5 个“域（Domain）”，找到第一个匹配的就立即返回：

```text
优先级从高到低：
1. NSArgumentDomain        （启动参数域：Xcode Edit Scheme -> Arguments 传入的临时参数，调试神器！）
      ↓ 没找到继续往下
2. Application Domain      （应用域：你平时用 setObject:forKey: 存进硬盘 plist 的数据）
      ↓ 没找到继续往下
3. NSGlobalDomain          （全局域：系统级设置，如系统语言、地区格式）
      ↓ 没找到继续往下
4. Languages Domain        （语言域：按用户首选语言列表设置的本地化默认值）
      ↓ 没找到继续往下
5. NSRegistrationDomain    （注册域：你用 registerDefaults: 注入的内存默认值）
```

### 这个机制带来两个非常酷的用法：
1. **解释了 `registerDefaults:` 的行为**：因为 `NSRegistrationDomain` 排在最底层（第 5 位），所以只要应用域（第 2 位）里用户保存过值，就会优先返回用户的值；没保存过才落到第 5 位返回出厂默认值。
2. **Xcode 调试覆盖默认值**：在 Xcode 菜单栏 `Product -> Scheme -> Edit Scheme -> Run -> Arguments -> Arguments Passed On Launch` 里添加 `-isNightMode YES`，因为 `NSArgumentDomain` 排第 1 位，无需改代码就能临时强行覆盖 `NSUserDefaults` 里的配置！

## 四、监听 `NSUserDefaults` 的数据变化

当某个页面修改了配置（比如设置页切换了夜间模式），其他页面想自动感知并刷新 UI，有两种监听方式：

### 方式 1：监听系统通知 `NSUserDefaultsDidChangeNotification`

只要 `NSUserDefaults` 里**任意一个 Key** 发生了变化，系统就会发出这个通知：

```objc
// 1. 注册监听（例如在 viewDidLoad 中）
[[NSNotificationCenter defaultCenter] addObserver:self
                                         selector:@selector(userDefaultsDidChange:)
                                             name:NSUserDefaultsDidChangeNotification
                                           object:nil];

// 2. 处理回调
- (void)userDefaultsDidChange:(NSNotification *)notification {
    BOOL isNight = [[NSUserDefaults standardUserDefaults] boolForKey:@"isNightMode"];
    NSLog(@"检测到 UserDefaults 变化，当前夜间模式：%d", isNight);
}

// 3. 记得在 dealloc 中移除（iOS 9+ 虽可自动移除，但显式移除是好习惯）
- (void)dealloc {
    [[NSNotificationCenter defaultCenter] removeObserver:self];
}
```
> **缺点**：这个通知不会告诉你具体是**哪一个 Key** 变了，只要有任何键变动都会触发。

### 方式 2：使用 KVO 精确监听某一个 Key

如果你只想监听 `"isNightMode"` 这一个键的变化，可以直接对 `standardUserDefaults` 添加 KVO：

```objc
// 1. 添加监听
[[NSUserDefaults standardUserDefaults] addObserver:self
                                        forKeyPath:@"isNightMode"
                                           options:NSKeyValueObservingOptionNew | NSKeyValueObservingOptionOld
                                           context:NULL];

// 2. 接收变化回调
- (void)observeValueForKeyPath:(NSString *)keyPath
                      ofObject:(id)object
                        change:(NSDictionary<NSKeyValueChangeKey,id> *)change
                       context:(void *)context {
    if ([keyPath isEqualToString:@"isNightMode"]) {
        BOOL newValue = [change[NSKeyValueChangeNewKey] boolValue];
        NSLog(@"isNightMode 精确变化为：%d", newValue);
    }
}

// 3. 必须在 dealloc 中移除 KVO，否则会崩溃！
- (void)dealloc {
    [[NSUserDefaults standardUserDefaults] removeObserver:self forKeyPath:@"isNightMode"];
}
```

> **注意**：如果你的 Key 名字里包含点号 `.`（比如 `"com.app.isNightMode"`），KVO 会把点号解析成嵌套路径（KeyPath）而导致监听失败！如果需要用 KVO 监听，Key 命名应避免使用点号（可用下划线 `_`）。

## 五、跨进程数据共享：App Group (`initWithSuiteName:`)

默认情况下，`[NSUserDefaults standardUserDefaults]` 只能被当前 App 自己访问。

但如果你的 App 开发了 **桌面小组件（Widget）**、**分享扩展（Share Extension）** 或 **Apple Watch 应用**，它们和主 App 属于不同的进程和沙盒。如何共享轻量数据？

1. 在 Xcode 的主 App 和 Extension 的 `Signing & Capabilities` 中，都添加 **App Groups**，并勾选同一个 Group ID（例如 `group.com.mycompany.myapp`）。
2. 代码中用 `initWithSuiteName:` 代替 `standardUserDefaults`：

```objc
NSUserDefaults *sharedDefaults = [[NSUserDefaults alloc] initWithSuiteName:@"group.com.mycompany.myapp"];

// 主 App 写入
[sharedDefaults setObject:@"晴 25°C" forKey:@"todayWeather"];

// 小组件（Widget）中用同样的 SuiteName 读取
NSString *weather = [sharedDefaults stringForKey:@"todayWeather"];
```

## 六、线程安全说明

苹果官方文档明确说明：**`NSUserDefaults` 类本身是线程安全的**。你可以在子线程和主线程同时调用 `setObject:forKey:` 和 `objectForKey:`，不会发生数据损坏或崩溃。

但要注意：**单次读写安全 ≠ 复合操作安全**。
比如两个线程同时做“读取计数 -> 加 1 -> 写回”（Read-Modify-Write），依然可能出现竞态条件导致少加一次，这种情况需要自己加锁或放到同一个串行队列中执行。
