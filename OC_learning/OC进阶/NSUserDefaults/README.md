# Objective-C `NSUserDefaults` 零基础完全指南

> **拼写小贴士**：标准的类名是 **`NSUserDefaults`**（注意 `User` 只有一个 `s`，末尾有复数 `s`）。新手最容易拼错成 `NSUserDefault` 或 `NSUsserDefault`，写代码时留意 Xcode 的自动补全哦！

---

## 一、一句话理解 `NSUserDefaults`

你可以把 `NSUserDefaults` 想象成 **App 自带的一本“轻量级小笔记本”**（本质上是一个保存在沙盒里的 `.plist` 键值对文件）。

在平时写代码时，我们定义的变量（比如 `BOOL isNightMode = YES;`）都存在**内存**里：
- **内存的特点**：速度快，但 App 一杀掉（重启），里面的数据就全清空了。
- **`NSUserDefaults` 的特点**：把数据写到手机的**硬盘（沙盒）**里。就算用户关闭 App、重启手机，下次打开 App 时依然能把数据原封不动地读出来。

---

## 二、它适合做什么？不适合做什么？

| 适合存什么（轻量级配置 / 状态） | 不适合存什么（千万别踩坑！） |
| :--- | :--- |
| 用户偏好设置（夜间模式、字体大小、音效开关） | **大量数据**（如几千条聊天记录、新闻列表 -> 用数据库 SQLite / WCDB） |
| 简单状态标记（是否首次启动、是否看过新手引导） | **大文件**（如图片、视频、音频 -> 存沙盒 `Documents` / `Caches` 目录） |
| 少量轻量数据（最近 10 条搜索记录、收藏的几个城市） | **敏感隐私数据**（如密码、Token、银行卡号 -> 用 `Keychain` 钥匙串） |
| 当前选中的语言、主题名、用户名等短信息 | **复杂的自定义对象图**（需要频繁查询/排序 -> 用数据库或 Core Data） |

## 三、与其他 iOS 数据持久化方案对比

iOS 开发中常见的持久化方案对比如下，帮助你建立全局视野：

| 持久化方案 | 本质 | 优点 | 缺点 | 典型场景 |
| :--- | :--- | :--- | :--- | :--- |
| **`NSUserDefaults`** | 系统管理的 `.plist` 文件 | **最简单**，单例全局可用，无需操心文件路径 | 只能存小数据、明文不加密、只支持基础类型 | 偏好设置、简单状态标记 |
| **Plist 文件** | 自己手动读写的 `.plist` | 结构清晰，可自定义存放路径 | 同样只支持基础类型，需自己管理路径 | 静态配置表、小型数组/字典 |
| **归档 (`NSSecureCoding`)** | 对象序列化为二进制文件 | 可以直接保存自定义 Model 对象 | 每次读写是全量操作，无法局部查询 | 保存单个复杂模型（如当前登录用户信息） |
| **SQLite / WCDB / Core Data** | 关系型数据库 | 支持海量数据、增删改查快、支持条件筛选排序 | 学习成本和配置成本较高 | 聊天记录、商品列表、离线缓存 |
| **Keychain（钥匙串）** | 系统级加密存储 | 极安全，且卸载 App 后数据仍可保留 | API 较繁琐（通常用第三方封装） | 密码、登录 Token、设备唯一标识 |
