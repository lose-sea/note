# 04 - 常见踩坑、最佳实践与速查表

这一篇帮你提前避开新手使用 `NSUserDefaults` 时 90% 的坑，并附上日常速查表与面试高频题。

---

## 一、新手最容易踩的 8 个坑

### 坑 1：取出的数组/字典永远是“不可变”的，直接修改会崩溃！

即使你存进去的是 `NSMutableArray` 或 `NSMutableDictionary`，取出来时系统返回的也是**不可变**的 `NSArray` / `NSDictionary`！

```objc
// 存了一个可变数组
NSMutableArray *mArr = [NSMutableArray arrayWithObjects:@"A", @"B", nil];
[[NSUserDefaults standardUserDefaults] setObject:mArr forKey:@"letters"];

// ❌ 错误：直接强转成可变数组并添加元素 -> 运行时直接崩溃！
// unrecognized selector sent to instance (NSArray 没有 addObject:)
NSMutableArray *saved = [[NSUserDefaults standardUserDefaults] objectForKey:@"letters"];
[saved addObject:@"C"]; // 💥 Crash!

// ✅ 正确：先 mutableCopy 一份，改完再存回去
NSMutableArray *mutableSaved = [[[NSUserDefaults standardUserDefaults] arrayForKey:@"letters"] mutableCopy];
[mutableSaved addObject:@"C"];
[[NSUserDefaults standardUserDefaults] setObject:mutableSaved forKey:@"letters"];
```

---

### 坑 2：数组或字典里混入了 `NSNull` 或自定义对象，导致崩溃！

很多时候我们把网络请求返回的 JSON 字典直接丢进 `NSUserDefaults`，结果偶发崩溃！
原因：**JSON 解析后，服务端返回的 `null` 会变成 `[NSNull null]` 对象**，而 `NSNull` **不是** plist 支持的类型！

```objc
NSDictionary *json = @{@"name": @"小明", @"nickname": [NSNull null]};
// ❌ 崩溃！NSInvalidArgumentException: Attempt to insert non-property list object
[[NSUserDefaults standardUserDefaults] setObject:json forKey:@"userInfo"];
```
**解决办法**：存储前过滤掉 `NSNull`，或者只提取需要的具体字段重新组装成干净的字典。

---

### 坑 3：把 `setObject:nil` 和字典赋值搞混

- `[defaults setObject:nil forKey:@"key"]`：**不会崩溃**，它等价于 `[defaults removeObjectForKey:@"key"]`（把该键删除）。
- 但是如果你写字面量字典 `@{@"key": someNilValue}` 再去存，构造字面量字典那一行就会直接崩溃！

---

### 坑 4：误用 `boolForKey:` / `integerForKey:` 判断“有没有存过”

- 如果从未存过 `@"showTips"`，`boolForKey:` 返回 `NO`，`integerForKey:` 返回 `0`。
- 如果你分不清“没存过”还是“存了 `NO`/`0`”，请用 `[defaults objectForKey:@"showTips"] != nil` 来判断，或者在启动时用 `registerDefaults:` 设置合理的默认值。

---

### 坑 5：用 `setObject:forKey:` 存 `NSURL`

```objc
NSURL *url = [NSURL URLWithString:@"https://www.apple.com"];
// ❌ 崩溃！NSURL 不是原生 plist 类型
[defaults setObject:url forKey:@"url"];

// ✅ 正确：使用专门的 URL API
[defaults setURL:url forKey:@"url"];
NSURL *savedURL = [defaults URLForKey:@"url"];
```

---

### 坑 6：把密码、Token 等敏感信息存进 `NSUserDefaults`

`NSUserDefaults` 底层是**明文 `.plist` 文件**，没有任何加密！
在越狱设备、iTunes 备份或调试工具下可以轻松直接读取。
- **原则**：密码、登录 Token、身份证号等敏感数据，一律使用 **Keychain（钥匙串）** 存储。

---

### 坑 7：把图片（`UIImage` 转 `NSData`）或大数组塞进 `NSUserDefaults`

虽然 `NSData` 可以存进去，但千万别把几百 KB 甚至几 MB 的图片/大列表塞进 `NSUserDefaults`！
因为 `NSUserDefaults` 启动时会把整个 plist 加载进内存，存大数据会造成：
- App 启动变慢
- 内存占用居高不下
- 每次写入小配置时拖慢整个 plist 的落盘速度

---

### 坑 8：忘了 Key 大小写敏感，或直接硬编码字符串

`"userName"` 和 `"username"` 是两个完全不同的 Key。
**最佳实践**：用 `static NSString * const` 定义常量，或者像 [02 篇](./02-存储自定义对象与实战场景.md) 中那样封装成一个专门的 `AppSettings` 工具类。

## 二、日常开发速查表（Cheat Sheet）

| 需求 | 代码写法 |
| :--- | :--- |
| 获取单例 | `NSUserDefaults *ud = [NSUserDefaults standardUserDefaults];` |
| 存 / 取 `NSString` | `[ud setObject:@"hi" forKey:k];` / `[ud stringForKey:k];` |
| 存 / 取 `BOOL` | `[ud setBool:YES forKey:k];` / `[ud boolForKey:k];` |
| 存 / 取 `NSInteger` | `[ud setInteger:10 forKey:k];` / `[ud integerForKey:k];` |
| 存 / 取 `float` / `double` | `[ud setDouble:3.14 forKey:k];` / `[ud doubleForKey:k];` |
| 存 / 取 `NSArray` | `[ud setObject:arr forKey:k];` / `[ud arrayForKey:k];` |
| 存 / 取 `NSDictionary` | `[ud setObject:dict forKey:k];` / `[ud dictionaryForKey:k];` |
| 存 / 取 `NSDate` | `[ud setObject:date forKey:k];` / `[ud objectForKey:k];` |
| 存 / 取 `NSData` | `[ud setObject:data forKey:k];` / `[ud dataForKey:k];` |
| 存 / 取 `NSURL` | `[ud setURL:url forKey:k];` / `[ud URLForKey:k];` |
| 判断 Key 是否存在 | `[ud objectForKey:k] != nil` |
| 删除单个 Key | `[ud removeObjectForKey:k];` |
| 注册默认值（不落盘） | `[ud registerDefaults:@{k: @YES}];` |
| 清空当前 App 所有数据 | `[ud removePersistentDomainForName:NSBundle.mainBundle.bundleIdentifier];` |
| App Group 共享实例 | `[[NSUserDefaults alloc] initWithSuiteName:@"group.xxx"];` |

## 三、常见面试题自测

### Q1：`NSUserDefaults` 支持哪些数据类型？能直接存自定义对象吗？
> **答**：支持 6 种基础 plist 对象类型（`NSString`、`NSNumber`、`NSData`、`NSDate`、`NSArray`、`NSDictionary`）以及便捷封装的 `BOOL`、`NSInteger`、`float`、`double`、`NSURL`。不能直接存自定义对象（会抛出 `NSInvalidArgumentException` 崩溃），需要先转成字典，或通过 `NSSecureCoding` 归档为 `NSData` 再存。

### Q2：往 `NSUserDefaults` 存入 `NSMutableArray`，取出来是什么类型？
> **答**：取出来永远是**不可变**的 `NSArray`。如果要修改，必须先调用 `mutableCopy` 转为可变数组，修改后再重新存入。

### Q3：`NSUserDefaults` 是线程安全的吗？数据存在哪？
> **答**：单次读写操作是线程安全的。数据以明文 plist 文件形式保存在沙盒的 `Library/Preferences/<BundleID>.plist` 中，底层通过内存缓存 + 系统进程 `cfprefsd` 异步落盘实现高性能。

### Q4：为什么不推荐把大量数据或用户密码存到 `NSUserDefaults`？
> **答**：
> 1. **性能问题**：`NSUserDefaults` 首次访问会将整个 plist 加载到内存中，大数据会导致启动变慢和内存暴涨。
> 2. **安全问题**：plist 文件以明文保存，没有加密保护，密码和 Token 等敏感信息应存放在 `Keychain` 中。

### Q5：现在还需要调用 `synchronize` 吗？
> **答**：不需要。在现代 iOS（iOS 12+）中，系统通过 `cfprefsd` 自动可靠地异步落盘，苹果官方已明确指出 `synchronize` 是多余的，频繁调用反而可能造成性能损耗。
