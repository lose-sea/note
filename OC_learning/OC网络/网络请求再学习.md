# 网络请求再学习

## 网络请求的步骤

1. 创建请求地址

确定接口地址，处理路径和查询参数（如 `?key=xxx&city=beijing`）。

1. 创建请求类

2. 创建会话

   1. 配置会话 

   创建 `NSURLSessionConfiguration`，设置超时时间、缓存策略、是否允许蜂窝网络等。这一步决定了网络请求的“基调”（默认、临时、后台）。

   1. 创建会话 

   利用上一步的配置，生成 `NSURLSession` 实例。如果不需要代理监听（如进度），直接用 `[NSURLSession sharedSession]` 即可。

3. 生成任务

根据业务需求选择任务类型（`DataTask` / `DownloadTask` / `UploadTask`），并传入 URL 或 Request 对象。**此时任务处于 `suspended`（挂起）状态，还未开始联网。**

4. 启动任务

调用 `[task resume]`

5. 处理响应数据 

如果自定义了 `delegate` 且会话不再使用，需调用 `[session finishTasksAndInvalidate]` 或 `[session invalidateAndCancel]` 来打破 `session` 对 `delegate` 的强引用。

6. 清理会话



## 创建请求地址

在开始学习的时候, 我们创建URL一般是直接使用字符串, 这种方式只适合静态地址 (没有中文, 没有空格, 没有特殊符号) 

`NSURL *url = [NSURL URLWithString:@"https://api.weatherapi.com/v1/forecast.json"];`



## 创建请求类

在 `NSURLSession` 中，苹果提供了一个非常便捷的方法：

```objc
- (NSURLSessionDataTask *)dataTaskWithURL:(NSURL *)url;
```

如果你直接传入 `URL`，系统会在**内部自动帮你创建一个默认的 `NSURLRequest`**（默认使用 `GET` 方法，默认超时时间，默认缓存策略）。在这种情况下，不需要写 `NSURLRequest` 的代码，任务就直接生成了 

通过这种方式直接生成任务就不用去专门创建请求类了

### 完整步骤 (显式创建)

如果请求稍微复杂一点（比如 **POST** 请求、需要加 **Headers**（如 Token）、需要上传 **Body** 数据），你就**必须**显式地创建 `NSMutableURLRequest`。

```objc
// 创建请求类
    NSMutableURLRequest* request = [NSMutableURLRequest requestWithURL: url];
    // HTTP 方法
    request.HTTPMethod = @"GET";
    // 时间阈值
    request.timeoutInterval = 15;
```

## 创建会话

在iOS中, 创建会话共有3种方式,分别对应不同的业务复杂度

### 1. 共享单例会话

直接使用系统提供的全局单例对象。

```
NSURLSession *session = [NSURLSession sharedSession];
```

+ **适用场景**：简单的、一次性的 GET/POST 请求，且不需要监听上传/下载进度。
+ **特点**：使用系统默认配置（类似浏览器），**无法自定义超时时间、缓存策略**，且**无法设置 Delegate**。所有回调只能通过 `completionHandler`（闭包）处理。
+ **内存管理**：无需管理，它是个单例，App 生命周期内一直存在。

### 2. 基于配置的会话（无代理，仅闭包回调）

使用 `NSURLSessionConfiguration` 来创建，但**不设置代理**（传入 `nil`），所有的数据返回都靠 Block 闭包。

```
NSURLSessionConfiguration *config = [NSURLSessionConfiguration defaultSessionConfiguration];
config.timeoutIntervalForRequest = 30.0;

// 注意：delegate 传 nil，delegateQueue 传 nil 或主队列
NSURLSession *session = [NSURLSession sessionWithConfiguration:config 
                                                      delegate:nil 
                                                 delegateQueue:[NSOperationQueue mainQueue]];
```

+ **适用场景**：需要自定义超时、缓存策略或额外 Headers，但不需要监听进度（如普通的 JSON 接口请求）。
+ **特点**：灵活度高于 `sharedSession`，但由于没有 Delegate，无法处理需要身份验证（如客户端证书）或重定向的复杂场景。
+ **内存管理**：因为 `delegate` 是 `nil`，不存在循环引用问题，会话用完后系统会自动释放，通常不需要手动 invalidate。 

> ` NSURLSession* session = [NSURLSession sessionWithConfiguration: [NSURLSessionConfiguration defaultSessionConfiguration]];` 相当于
>
> ```objc
>     NSURLSessionConfiguration* config = [NSURLSessionConfiguration defaultSessionConfiguration];
> NSURLSession *session = [NSURLSession sessionWithConfiguration:config 
>                                                       delegate:nil 
>                                                  delegateQueue:[NSOperationQueue mainQueue]];
> ```
>
> 

### 3. 基于配置 + 自定义代理（全功能模式）

这是**最强大、最复杂**的模式

```
NSURLSession *session = [NSURLSession sessionWithConfiguration:config 
                                                      delegate:self 
                                                 delegateQueue:[NSOperationQueue mainQueue]];
```

+ **适用场景**：大文件下载（需要进度条）、大文件上传、需要处理 HTTPS 证书校验（`didReceiveChallenge`）、需要拦截服务器重定向。
+ **特点**：可以实时接收到 `NSURLSessionDelegate`、`NSURLSessionDownloadDelegate` 等协议中的回调。
+ 内存管理：**会话对象会强引用（retain）代理对象 `self`**。如果 `self` 是 ViewController，这就会造成**循环引用**，导致页面 `dealloc` 不被调用，造成内存泄漏。

## 生成任务



| 任务类型                     | 创建方法前缀          | 核心特征                                                     | 适用场景                                     |
| :--------------------------- | :-------------------- | :----------------------------------------------------------- | :------------------------------------------- |
| **NSURLSessionDataTask**     | `dataTaskWith...`     | 数据一次性加载到 **内存（NSData）** 中返回。                 | 调用 JSON 接口、获取图片二进制数据（小图）。 |
| **NSURLSessionUploadTask**   | `uploadTaskWith...`   | 专门负责把数据**发送**给服务器，支持后台上传。               | 提交头像、上传日志文件、表单提交。           |
| **NSURLSessionDownloadTask** | `downloadTaskWith...` | 数据直接写入**磁盘临时文件（NSURL）**，不占用 App 内存。支持断点续传。 | 下载视频、更新包、大体积 ZIP 文件。          |
| **NSURLSessionStreamTask**   | `streamTaskWith...`   | 建立 TCP/IP 流式连接，读写数据按流处理。                     | 即时通讯（IM）、WebSocket 长连接。           |

笔者目前还处于初始学习过程, 只接触到 NSURLSessionDataTask 

任务的回调方式, 闭包(Block) 和 代理 (delegate) 

| 回调方式                              | 方法特征                                                     | 优点                                                         | 缺点 / 限制                                                  |
| :------------------------------------ | :----------------------------------------------------------- | :----------------------------------------------------------- | :----------------------------------------------------------- |
| **Block 闭包** （Completion Handler） | 方法名末尾带 `completionHandler:` 参数。                     | **代码紧凑**，发起和处理的逻辑写在一起，易于阅读。 **无循环引用风险**（若会话无代理，则无需关心内存泄漏）。 | **无法获取中间进度**（DownloadTask 除外，它有单独的进度闭包）。 无法处理服务器要求客户端证书（Authentication Challenge）。 无法拦截重定向。 |
| **Delegate 代理** （响应协议方法）    | 创建会话时传入 `delegate:self`，并实现 `<NSURLSessionDelegate>` 等协议。 | **精细控制**：可以实时监听 `didWriteData`（进度）、`didReceiveChallenge`（证书校验）、`willPerformHTTPRedirection`（重定向）。 **分片接收数据**（在 `didReceiveData` 中手动拼接）。 | **代码分散**，逻辑割裂在多个回调方法中。 **极易造成循环引用**，必须手动调用 `invalidateAndCancel` 断开强引用。 |
