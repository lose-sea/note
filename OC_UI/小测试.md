# 练习题：「简易任务清单」App

> 综合考察：UITableView · 自定义 Cell · UINavigationController · Delegate 回传 · UIToolbar

---

## 整体结构

使用 `UINavigationController` 作为根容器，管理以下三个页面。

---

## 第一页 — 任务列表页 `TaskListViewController`

- 用 `UITableView` 展示任务列表，初始有 3 条 hardcode 的假数据
- 每个 cell 显示两个信息：任务名称（左）、状态标签（右，显示「待完成」或「已完成」）
- Cell 必须用**自定义 `UITableViewCell` 子类**实现，不能使用系统自带的 `textLabel` / `detailTextLabel`
- 导航栏右侧放一个 `UIBarButtonItem`，标题为「添加」，点击跳转到第二页
- 点击某一行，跳转到第三页（详情页），并把对应任务数据传过去

---

## 第二页 — 添加任务页 `AddTaskViewController`

- 页面标题：「新建任务」
- 一个 `UITextField`，placeholder 为「请输入任务名称」
- 一个 `UIButton`，标题为「确认添加」
- 点击按钮后：把新任务**传回第一页**并 pop，第一页列表要能刷新出新数据
- 传值方式：**用 Delegate 协议**实现回传（不要用属性直接赋值）

---

## 第三页 — 任务详情页 `TaskDetailViewController`

- 显示任务名称（`UILabel`）
- 显示当前状态（`UILabel`，「待完成」/ 「已完成」）
- 页面底部放一个 `UIToolbar`，上面有一个 `UIBarButtonItem`，标题为「标记为已完成」
- 点击后，该按钮变为不可用（`enabled = NO`），状态 label 同步更新为「已完成」

---

## 验收标准

| 考察点        | 要求                                      |
| ------------- | ----------------------------------------- |
| 自定义 Cell   | 有独立的 `.h/.m` 文件，用代码布局子控件   |
| Cell 复用     | 使用 `dequeueReusableCellWithIdentifier:` |
| 页面跳转      | push / pop 正常，无黑屏无崩溃             |
| Delegate 回传 | 协议定义规范，AddVC 持有 weak delegate    |
| 数据同步      | 添加后列表刷新，详情页改状态后 UI 响应    |
| UIToolbar     | 正确添加到详情页底部                      |

---

## 提示

- 任务数据推荐用一个简单的 Model 类 `TaskModel` 来表示（有 `name` 和 `isCompleted` 两个属性即可），也可以用 `NSDictionary`，但 Model 类更规范
- 不需要做持久化（不用存文件 / 数据库），内存数据即可
- 布局用 `frame` 手写，暂时不需要 AutoLayout
