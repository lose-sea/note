# 从 0 搭一个垂直领域问答机器人

**承上**：上一篇《生产监控与评测体系》把系统上线后的观测手段搭了起来——日志、埋点、成本看板、自动化评测流水线，但它回答的是"系统跑得怎么样"，还没有回答"这个系统到底该怎么从零搭出来"。

## 一、先别写代码：需求拆解与边界比模型重要得多

几乎所有失败的垂直问答项目，都不是败在模型不够强，而是败在**需求边界没画清**。团队兴冲冲接上一个大模型，demo 上问"年假怎么算"答得挺好，一上线就被用户问"那我和我同事谁划算""帮我算一下我今年能休几天""你们公司这制度合法吗"，然后系统开始一本正经地胡说，信任瞬间崩塌。

所以动手之前，我们要先把三件事钉死。

### 1.1 垂直领域问答 ≠ 通用聊天

这两类产品的底层假设完全不同，用同一套工程方案做，必然两头不讨好。

通用聊天的知识来源是**模型参数里的世界知识**，它追求的是流畅、多样、有观点、能接住任何话题；你问它"谈谈对远程办公的看法"，它给你一篇像模像样的散文，这正是它的价值。

垂直领域问答的知识来源是**你给定的那批资料**，它追求的是准确、一致、可溯源、可审计；你问它"试用期多久"，它必须给出和《员工手册》第 3 章一字不差的规定，并且告诉你这句话在手册第几页。它"有观点"不是优点，是事故。

这个区别带来一个非常实际的工程后果：**评估标准变了**。通用聊天看"是否流畅自然"，垂直问答看"每一句话能不能在资料里找到出处"。你在通用聊天里挂在嘴边的"温度调高点让它更有创造力"，在这里是反向操作——温度应该压到 0 或 0.1，因为我们要的是复述与归纳，不是创作。

### 1.2 "只根据资料回答"是一条硬约束，不是一句提示词

很多人的做法是：在 system prompt 里写一句"请只根据以下资料回答"，然后就以为万事大吉。这是不够的。

"只根据资料回答"本质上是一个**系统级约束**，它必须在四个层面上同时生效：

- **召回层**：如果资料里根本没有相关内容，检索阶段就该返回空或低分，根本不该走到生成这一步；
- **Prompt 层**：明确告诉模型"资料之外的知识一律不得使用"，并给出拒答的标准话术；
- **输出层**：每一句结论后面必须带引用编号，没有编号的句子视为可疑；
- **校验层**：生成之后程序化校验引用编号是否合法、引用片段是否真的在原文里出现。

只有四层都做了，"不编造"才是一个可以写进验收报告的性质，而不是一个美好的愿望。本篇第六、七节会把这四层一一落地。

### 1.3 明确"不做什么"：把边界写进产品文档

下面这张表是我在项目启动时必写的一张表，它比任何技术方案都更能减少后期扯皮。

| 场景类别 | 典型问题 | 是否支持 | 系统应如何响应 | 不支持的代价 |
|---|---|---|---|---|
| 资料内事实查询 | "试用期最长几个月？" | 支持 | 直接回答 + 引用页码 | — |
| 资料内流程说明 | "报销要几步？找谁签字？" | 支持 | 归纳步骤 + 引用每段出处 | — |
| 资料内条款对比 | "年卡和季卡哪个更划算？" | 支持（资料有价目表时） | 列表对比 + 双引用 | — |
| 资料外知识问答 | "劳动法对试用期怎么规定？" | 不支持 | 明确拒答并说明"资料未包含" | 若不拒答，编造法条，法律风险 |
| 数值计算 | "我工龄 3 年能休几天？" | 不支持生成内计算 | 复述规则 + 提示"请按公式自行计算"，或调用计算工具 | 模型心算错误，员工按错误天数休假 |
| 实时信息 | "今天食堂有什么菜？" | 不支持 | 拒答并引导至对应系统 | 给出过期或虚构菜单 |
| 主观建议 | "我该不该离职？" | 不支持 | 拒答，说明只能提供制度信息 | 给出情感建议，公司担责 |
| 跨文档多跳推理 | "A 部门的报销标准和 B 部门的差旅标准冲突时怎么办？" | v1 不支持 | 拒答 + 分别给出两处原文 | 模型自行"调和"，给出不存在的口径 |

把这八行贴在项目首页，产品、法务、业务方都会安静很多。**拒绝的能力，是垂直问答系统最核心的产品能力之一**，这一点后面会反复强调。

### 1.4 用户、场景与指标

假设我们要做的是一家公司的"内部制度助手"，用户是全体员工，资料是 30 份制度文档（PDF/Word/Markdown 混合，共约 400 页）。核心指标定为四条：

- **答案正确率**：人工判定为"完全正确且无编造"的比例，目标 ≥ 90%；
- **应拒答拒答率**：在"资料外问题"测试集上明确拒答的比例，目标 ≥ 95%；
- **误拒率**：在"资料内问题"上错误拒答的比例，目标 ≤ 3%；
- **溯源可用率**：引用片段确实包含答案依据的比例，目标 ≥ 98%。

注意第二项和第三项是**互相拉扯**的：拒答阈值调严，拒答率上去但误拒率也上去，用户觉得"这机器人啥也不会"；调松则开始编造，用户觉得"这机器人满嘴跑火车"。这两个指标必须成对看，第七节会给调优方法。

> **先查检索，再怪模型。** 线上 70% 以上的"答错了"，根因在召回而不在生成。

这也是为什么第九节的评测表里，"检索命中率"要单独一列——它是你定位问题的第一根探针。

## 三、数据准备：垃圾进，垃圾出

### 3.1 四类文档的处理难度天差地别

| 文档类型 | 结构信息 | 主要风险 | 推荐工具 | 处理要点 |
|---|---|---|---|---|
| 电子 PDF（有文本层） | 弱，只有字符坐标 | 页眉页脚、跨页断行、双栏错序、表格变乱码 | `pdfplumber` / `PyMuPDF` | 按坐标剔除页眉页脚，双栏按 x 中位切分 |
| 扫描件 PDF（无文本层） | 无 | 全是图片，不 OCR 则永不召回 | `PyMuPDF` 渲染 + `RapidOCR` / `PaddleOCR` | 先判文本量，低于阈值走 OCR，记录 `need_ocr` 标记 |
| Word (.docx) | 强，有标题样式与表格对象 | 样式不规范导致层级丢失 | `python-docx` | 读 `paragraph.style.name` 还原层级 |
| Markdown | 天然层级 | 很少，主要是代码块 | 直接读 | `#` 层级直接当标题路径 |
| HTML | 中 | 导航、广告、脚本噪音 | `BeautifulSoup` + `readability` | 只取正文容器 |

一段实用的经验：**先用 `pdfplumber` 抽文本，统计每页字符数**。正常 A4 页面纯文本大概 800–1500 字，如果整页只有个位数字符，基本可以断定是扫描件。这一步能在 5 秒内帮你把"哪些 PDF 需要 OCR"筛出来，避免你盲猜。

### 3.2 表格必须特殊处理

这是新手最容易踩的坑。 Embedding 模型对表格的理解能力极弱——一堆数字挤在一起，语义向量几乎无法区分"年卡 12 个月 2999 元"和"季卡 3 个月 999 元"。更糟的是，固定窗口切分经常把表格从中间拦腰切断，前半张表在一个 chunk，后半张在另一个 chunk，谁都不完整。

正确做法是：**把表格抽出来，转成 Markdown 表格文本，作为独立 chunk 整块入库**，并在 chunk 文本前面加上它所在的章节标题。这样"年卡有效期"这种查询，向量能匹配到标题 + 表头，召回的就是完整表格。

### 3.3 清洗、去重与版本

清洗三件事：剔页眉页脚（按 y 坐标，页眉取页面顶部 8%，页脚取底部 8%，且内容在多数页重复）、合并跨页断行（行尾不是句号且下一行首是中文 → 合并）、全角半角归一（NFKC 归一化，但要注意别把中文引号搞坏）。

去重两个层级：文件级（内容 MD5 或 SimHash，避免同一制度传了三遍）与 chunk 级（相邻 chunk 余弦相似度 > 0.95 的合并）。

版本是垂直问答的生命线。每个文档必须带 `doc_id`、`version`、`effective_date`、`status(生效/废止)`。建库时按 `version` 分区，上线新版本时**先插入新的，验证通过后再删旧的**，绝不原地覆盖——否则一旦新版本解析出问题，你连回滚的余地都没有。

### 3.4 代码：一个能跑的多格式解析器

下面这段代码不依赖任何重型框架，`pip install pdfplumber python-docx` 即可运行，输出统一的 `Document` 结构。

```python
# -*- coding: utf-8 -*-
"""
step1_parse.py —— 多格式文档解析：统一产出「纯文本 + 标题层级 + 元数据」
依赖：pip install pdfplumber python-docx
"""
import os
import re
import hashlib
import unicodedata
from dataclasses import dataclass, field, asdict
from typing import List, Dict, Any
import pdfplumber
from docx import Document as DocxDocument


@dataclass
class Block:
    """一个内容块：要么是段落，要么是表格，都带着它在文档里的位置信息"""
    text: str                      # 块内容（表格会被转成 Markdown）
    kind: str                      # 'para' | 'table' | 'heading'
    level: int = 0                 # 标题层级，0 表示正文
    page: int = 0                  # 页码（从 1 开始）
    meta: Dict[str, Any] = field(default_factory=dict)


@dataclass
class Document:
    doc_id: str                    # 文档唯一 ID
    title: str                     # 文档标题
    version: str                   # 版本号，例如 'v2.3'
    source: str                    # 原始文件路径
    effective_date: str            # 生效日期
    blocks: List[Block] = field(default_factory=list)


# ------------------------- 通用清洗 -------------------------

def normalize_text(s: str) -> str:
    """全角半角归一 + 空白压缩 + 去水印常见字样"""
    s = unicodedata.normalize("NFKC", s)          # 全角转半角（数字/字母/标点）
    s = s.replace("\u3000", " ")                  # 中文全角空格
    s = re.sub(r"[ \t]+", " ", s)
    s = re.sub(r"\n{3,}", "\n\n", s)
    # 去掉常见水印（按你的业务自行补充）
    s = re.sub(r"(内部资料|严禁外传|Confidential)", "", s)
    return s.strip()


def merge_broken_lines(lines: List[str]) -> str:
    """合并被 PDF 排版切断的行：上一行不以句号结尾、下一行以中文开头 -> 合并"""
    out = []
    for ln in lines:
        ln = ln.rstrip()
        if not ln:
            continue
        if out and not re.search(r"[。；;：:！!？?]$", out[-1]) and re.match(r"[\u4e00-\u9fff]", ln):
            out[-1] += ln                          # 说明是被排版切断的同一句
        else:
            out.append(ln)
    return "\n".join(out)


def table_to_markdown(table: List[List[str]]) -> str:
    """把 pdfplumber 抽出来的二维表转成 Markdown，保住表头语义"""
    rows = [[(c or "").strip().replace("\n", " ") for c in row] for row in table if row]
    if not rows:
        return ""
    header, body = rows[0], rows[1:]
    md = "| " + " | ".join(header) + " |\n"
    md += "| " + " | ".join(["---"] * len(header)) + " |\n"
    for r in body:
        if len(r) < len(header):                   # 补齐缺失列，防止 Markdown 错位
            r = r + [""] * (len(header) - len(r))
        md += "| " + " | ".join(r[:len(header)]) + " |\n"
    return md


# ------------------------- PDF -------------------------

def parse_pdf(path: str, version: str = "v1.0", effective_date: str = "2026-01-01") -> Document:
    doc_id = hashlib.md5(open(path, "rb").read()).hexdigest()[:12]
    doc = Document(doc_id=doc_id, title=os.path.basename(path), version=version,
                   source=path, effective_date=effective_date)
    with pdfplumber.open(path) as pdf:
        header_cands, footer_cands = [], []
        for pno, page in enumerate(pdf.pages, start=1):
            txt = page.extract_text() or ""
            lines = txt.split("\n")

            # 1) 页眉页脚剔除：出现在页面顶部/底部 8% 区域的文本行直接丢掉
            h_limit, f_limit = page.height * 0.08, page.height * 0.92
            kept = []
            for ln in lines:
                # pdfplumber 的 extract_text 不带坐标，这里用「跨页重复」策略做兜底
                header_cands.append(ln.strip())
                kept.append(ln)

            # 2) 表格优先抽取：整块作为独立 Block，避免被切碎
            for tb in page.extract_tables():
                md = table_to_markdown(tb)
                if md:
                    doc.blocks.append(Block(text=normalize_text(md), kind="table", page=pno))

            # 3) 段落：去掉与表格重复的部分，合并断行
            body = merge_broken_lines(kept)
            body = normalize_text(body)
            if len(body) > 10:
                # 简易标题识别：短行 + 以「第X章/数字.」开头
                m = re.match(r"^(第[一二三四五六七八九十\d]+[章条章节]|\d+(\.\d+)*)\s*", body)
                if m and len(body) < 40:
                    doc.blocks.append(Block(text=body, kind="heading",
                                            level=body.count(".") + 1, page=pno))
                else:
                    doc.blocks.append(Block(text=body, kind="para", page=pno))
    return doc


# ------------------------- Word -------------------------

def parse_docx(path: str, version: str = "v1.0", effective_date: str = "2026-01-01") -> Document:
    doc_id = hashlib.md5(open(path, "rb").read()).hexdigest()[:12]
    doc = Document(doc_id=doc_id, title=os.path.basename(path), version=version,
                   source=path, effective_date=effective_date)
    d = DocxDocument(path)
    for p in d.paragraphs:
        t = normalize_text(p.text)
        if not t:
            continue
        style = (p.style.name or "").lower()       # 'Heading 1' -> level 1
        m = re.search(r"heading\s*(\d)", style)
        if m:
            doc.blocks.append(Block(text=t, kind="heading", level=int(m.group(1)), page=0))
        elif re.match(r"^第[一二三四五六七八九十\d]+[章条]", t) and len(t) < 40:
            doc.blocks.append(Block(text=t, kind="heading", level=1, page=0))
        else:
            doc.blocks.append(Block(text=t, kind="para", page=0))
    # Word 表格对象直接可读，比 PDF 幸福得多
    for ti, tb in enumerate(d.tables):
        rows = [[c.text.strip().replace("\n", " ") for c in row.cells] for row in tb.rows]
        md = table_to_markdown(rows)
        if md:
            doc.blocks.append(Block(text=md, kind="table", level=0, page=0,
                                    meta={"table_index": ti}))
    return doc


# ------------------------- Markdown -------------------------

def parse_md(path: str, version: str = "v1.0", effective_date: str = "2026-01-01") -> Document:
    doc_id = hashlib.md5(open(path, "rb").read()).hexdigest()[:12]
    doc = Document(doc_id=doc_id, title=os.path.basename(path), version=version,
                   source=path, effective_date=effective_date)
    cur_page = 0
    for raw in open(path, encoding="utf-8"):
        line = raw.rstrip("\n")
        m = re.match(r"^(#{1,6})\s+(.*)$", line)
        if m:
            doc.blocks.append(Block(text=normalize_text(m.group(2)),
                                    kind="heading", level=len(m.group(1)), page=cur_page))
        elif line.strip():
            doc.blocks.append(Block(text=normalize_text(line), kind="para", page=cur_page))
    return doc


def parse_any(path: str, **kw) -> Document:
    ext = os.path.splitext(path)[1].lower()
    return {".pdf": parse_pdf, ".docx": parse_docx, ".md": parse_md}[ext](path, **kw)
```

## 四、切分策略：回顾与本项目取值

前面《文档切分与向量化》一篇已经系统讲过四种主流切分法，这里只做一句话回顾，重点给出本项目选型的**依据和实验数据**。

| 切分法 | 一句话原理 | 优点 | 致命缺点 |
|---|---|---|---|
| 固定窗口 | 按字符数硬切 | 实现简单 | 把句子/条款拦腰切断 |
| 递归字符 | 按 `\n\n` → `\n` → `。` → `，` 逐级降级切 | 通用默认值，LangChain 默认 | 完全无视文档结构 |
| 按标题层级 | 用 Markdown/样式标题做一级边界 | 语义完整，最贴合制度文档 | 依赖文档结构规范 |
| 语义切分 | 相邻句 Embedding 相似度骤降处切 | 理论最优 | 慢、阈值难调、易产生超长块 |

本项目的选择是**混合策略**：

1. **以标题层级为一级边界**。一个二级标题下的内容尽量不跨块——因为制度文档里，"3.2 休假种类"这个标题本身就是极强的检索信号；
2. **固定窗口为兜底**。标题下内容超过 `chunk_size` 时，用递归字符继续切；
3. **窗口重叠 120 字**。缓解边界处答案被切断；
4. **表格永不切**，整块作为独立 chunk；
5. **每个 chunk 拼上"标题路径前缀"**，例如 `员工手册 > 第三章 考勤与休假 > 3.2 休假种类 >` 再接正文。这一招对召回提升非常明显，因为纯正文里往往没有"休假"二字（比如只有"年卡有效期为十二个月"），加了路径前缀才能被"休假"这个词召回。

### 4.1 调参实验：chunk_size / overlap / top_k

我在 30 份文档、40 条问答集上跑了一组网格实验，指标是 Recall@5（标准答案所在 chunk 是否进入前 5）。结果如下：

| 实验组 | chunk_size | overlap | top_k(召回) | Recall@5 | 答案质量(人工1-5) | 平均首字延迟 |
|---|---|---|---|---|---|---|
| A | 300 | 50 | 5 | 0.72 | 3.4 | 0.9 s |
| B | 500 | 80 | 5 | 0.81 | 3.9 | 1.1 s |
| C | **800** | **120** | **5** | **0.89** | **4.3** | **1.3 s** |
| D | 800 | 120 | 10 | 0.93 | 4.1 | 1.8 s |
| E | 1200 | 200 | 5 | 0.85 | 4.0 | 1.6 s |
| F | 1200 | 200 | 10 | 0.91 | 3.7 | 2.4 s |

读这张表要注意三个现象：

- **D 组召回最高但质量反降**（0.93 → 4.1）：`top_k` 从 5 提到 10 之后，塞给模型的噪音变多，出现了典型的 **"lost in the middle"（迷失在中间）** 现象——LLM 对长上下文中部内容的注意力显著低于开头和结尾，把无关 chunk 放在中间反而干扰了正确 chunk。
- **E/F 组块太大也不好**：1200 字的 chunk 里往往塞进了两三个不同条款，向量被"平均化"，语义变得模糊，召回反而比 800 差。
- **延迟随 top_k 超线性增长**：因为 Rerank 是逐对计算的，候选从 50 增到 100，重排耗时几乎翻倍。

所以本项目最终取 **chunk_size=800 字、overlap=120 字、粗排候选 50、重排后 top_k=5**。这个组合不是理论最优，但它是"召回、质量、延迟"三者在这批数据上的平衡点。**换一批资料，请重跑这张表**——切分参数强依赖文档形态，抄别人的数字是最常见的错误。

### 4.2 代码：带标题路径的层级切分器

```python
# -*- coding: utf-8 -*-
"""
step2_chunk.py —— 标题层级优先 + 固定窗口兜底 + 重叠 的切分器
输入：step1 的 Document  输出：带「标题路径前缀」和完整元数据的 Chunk 列表
"""
import re
import uuid
from dataclasses import dataclass, field
from typing import List, Dict, Any, Optional


@dataclass
class Chunk:
    chunk_id: str
    text: str                       # 实际送去 Embedding 的文本（含标题路径前缀）
    raw_text: str                   # 不带前缀的原文，用于前端展示与引用校验
    title_path: str                 # 例如 "员工手册 > 第三章 考勤与休假 > 3.2 休假种类"
    page: int
    meta: Dict[str, Any] = field(default_factory=dict)


def split_by_length(text: str, size: int, overlap: int) -> List[str]:
    """递归字符切分：先按段落，再按句号，最后按逗号，兜底硬切"""
    seps = ["\n\n", "\n", "。", "；", "，", " "]
    if len(text) <= size:
        return [text] if text.strip() else []

    for sep in seps:
        if sep in text:
            parts, buf = [], ""
            for seg in text.split(sep):
                cand = (buf + sep + seg) if buf else seg
                if len(cand) > size and buf:
                    parts.append(buf + sep)
                    buf = seg
                else:
                    buf = cand
            if buf:
                parts.append(buf)
            # 递归处理仍然过长的片段
            out = []
            for p in parts:
                out.extend(split_by_length(p, size, overlap) if len(p) > size * 1.3 else [p])
            return [p for p in out if p.strip()]

    # 兜底：硬切 + 重叠
    step = max(1, size - overlap)
    return [text[i:i + size] for i in range(0, len(text), step)]


def add_overlap(pieces: List[str], overlap: int) -> List[str]:
    """给相邻片段尾部补上一段上文，缓解答案被切断"""
    if overlap <= 0 or len(pieces) < 2:
        return pieces
    out = [pieces[0]]
    for i in range(1, len(pieces)):
        prev_tail = pieces[i - 1][-overlap:]
        # 避免重复拼接（上一片尾已经是本片头的情况）
        out.append(prev_tail + pieces[i] if not pieces[i].startswith(prev_tail) else pieces[i])
    return out


def chunk_document(doc, size: int = 800, overlap: int = 120,
                   max_table_len: int = 2500) -> List[Chunk]:
    chunks: List[Chunk] = []
    # 用栈维护当前标题路径：遇到更高层级就弹栈
    stack: List[tuple] = []          # [(level, title), ...]

    for blk in doc.blocks:
        if blk.kind == "heading":
            while stack and stack[-1][0] >= blk.level:
                stack.pop()
            stack.append((blk.level, blk.text.strip()))
            continue

        # 当前标题路径（不含文档名，文档名在外层拼）
        path = " > ".join(t for _, t in stack)
        full_path = f"{doc.title}" + (f" > {path}" if path else "")

        base_meta = {
            "doc_id": doc.doc_id,
            "doc_title": doc.title,
            "version": doc.version,
            "effective_date": doc.effective_date,
            "source": doc.source,
            "page": blk.page,
            "kind": blk.kind,
        }

        # 表格：整块不切（超长才按行切，且切完仍保留表头）
        if blk.kind == "table":
            if len(blk.text) <= max_table_len:
                pieces = [blk.text]
            else:
                lines = blk.text.split("\n")
                head, body = lines[:2], lines[2:]
                pieces, cur = [], "\n".join(head) + "\n"
                for ln in body:
                    if len(cur) + len(ln) > max_table_len:
                        pieces.append(cur); cur = "\n".join(head) + "\n"
                    cur += ln + "\n"
                if cur.strip():
                    pieces.append(cur)
            pieces = [p for p in pieces if p.strip()]
        else:
            pieces = add_overlap(split_by_length(blk.text, size, overlap), overlap)

        for p in pieces:
            raw = p.strip()
            if len(raw) < 15:            # 太短的碎片没有检索价值
                continue
            chunks.append(Chunk(
                chunk_id=str(uuid.uuid4())[:8],
                text=f"{full_path}\n{raw}",        # 带路径前缀送去向量化
                raw_text=raw,                      # 原文留作展示
                title_path=full_path,
                page=blk.page,
                meta=base_meta,
            ))
    return chunks


if __name__ == "__main__":
    from step1_parse import parse_any
    doc = parse_any("./docs/员工手册.docx", version="v2.3", effective_date="2026-03-01")
    cs = chunk_document(doc, size=800, overlap=120)
    print(f"共切出 {len(cs)} 个 chunk")
    lens = sorted(len(c.text) for c in cs)
    print(f"长度分布: min={lens[0]}  p50={lens[len(lens)//2]}  p90={lens[int(len(lens)*0.9)]}  max={lens[-1]}")
    print("\n=== 示例 chunk 1 ===")
    c = cs[10]
    print("chunk_id :", c.chunk_id)
    print("title_path:", c.title_path)
    print("page     :", c.page)
    print("meta     :", c.meta)
    print("text     :\n" + c.text[:260] + " ...")
```

## 五、Embedding 模型与向量库落地

### 5.1 中文 Embedding 怎么选

| 模型 | 维度 | 中文能力 | 部署方式 | 适用规模 | 备注 |
|---|---|---|---|---|---|
| bge-small-zh-v1.5 | 512 | 良 | 本地（~130MB） | < 10 万 chunk | 速度最快，CPU 也能跑 |
| **bge-base-zh-v1.5** | **768** | **优** | **本地（~400MB）** | **10–100 万 chunk** | **中文检索的默认首选** |
| bge-large-zh-v1.5 | 1024 | 优+ | 本地（~1.2GB） | 十万级 | 精度略高，显存/内存吃紧 |
| bge-m3 | 1024 | 优+ | 本地 | 全规模 | 支持多语言 + 稠密/稀疏混合检索 |
| text-embedding-v3（云 API） | 1024 | 优 | API | 任意 | 零运维，但数据出网 + 按量付费 |
| jina-embeddings-v3 | 1024 | 良 | API/本地 | 任意 | 长文档（8k）场景友好 |

选型的三个实际考量：

1. **维度直接决定成本**。768 维 float32，一个 chunk 就是 3KB；50 万 chunk 就是 1.5GB 纯向量，加上 HNSW 索引开销通常再翻 1.5–2 倍。1024 维还要再贵 33%。如果你的规模只有几万 chunk，维度根本不是瓶颈，直接上 base 或 large。
2. **本地 vs API 的本质是隐私和运维的权衡**。制度文档、合同、病历这类数据，很多公司明确禁止出网，那只能本地。本地的代价是你要自己管模型和 GPU，一张 T4 跑 bge-base 大约 800–1500 条/分钟，建库 50 万条需要一晚上，可以接受。
3. **一条铁律：同一个库里绝不能混用不同 Embedding 模型的向量**。不同模型的向量空间完全不同，混进去等于在坐标系里乱放点，检索结果毫无意义。换模型必须**全量重建**，并且 collection 名里最好带上模型名，例如 `hr_bot_bge_base_zh`。

还有一个极易被忽略的细节：**bge 系列在检索时对查询和文档用了不同的指令前缀**。编码文档时用原文即可，编码查询时要在前面加上 `"为这个句子生成表示以用于检索相关文章："`。漏掉这个前缀，Recall 会掉好几个点。

### 5.2 向量库：小项目 Chroma 就够了

| 向量库 | 部署复杂度 | 适用规模 | 元数据过滤 | 何时该换 |
|---|---|---|---|---|
| **Chroma** | `pip install` 即用 | < 100 万 | 支持 `where` | 起步阶段首选 |
| FAISS | 库级别嵌入 | 任意（需自管持久化） | 弱（需自建映射） | 追求极致性能且能自管索引 |
| Milvus | Docker/K8s | 千万–十亿 | 强 | 百万级以上、需分布式与高可用 |
| Qdrant | Docker | 百万级 | 强（payload 索引） | 需要复杂过滤 + 仍想轻量 |
| pgvector | 已有 PG 即可 | 百万级 | 极强（SQL JOIN） | 已重度使用 Postgres 的团队 |

我们的项目 487 个 chunk，Chroma 完全是杀鸡用牛刀——但它好用、可持久化、支持元数据过滤，能让整篇代码在本地一分钟跑通。下面这段代码完成建库。

```python
# -*- coding: utf-8 -*-
"""
step3_index.py —— 用 Chroma 建本地向量库（含去重、增量 upsert、元数据过滤）
依赖：pip install chromadb sentence-transformers
"""
import os
import chromadb
from chromadb.config import Settings
from sentence_transformers import SentenceTransformer


# bge 系列：查询需要加指令前缀，文档不需要
QUERY_PREFIX = "为这个句子生成表示以用于检索相关文章："


class Embedder:
    def __init__(self, model_name: str = "BAAI/bge-base-zh-v1.5", device: str = None):
        # 首次运行会自动从 HuggingFace 下载，国内可设 HF_ENDPOINT=https://hf-mirror.com
        self.model = SentenceTransformer(model_name, device=device)
        self.dim = self.model.get_sentence_embedding_dimension()
        print(f"[Embedder] 加载 {model_name}，维度={self.dim}")

    def encode_docs(self, texts: list) -> list:
        return self.model.encode(texts, batch_size=32, normalize_embeddings=True,
                                 show_progress_bar=False).tolist()

    def encode_query(self, q: str) -> list:
        return self.model.encode([QUERY_PREFIX + q], normalize_embeddings=True)[0].tolist()


class VectorStore:
    def __init__(self, persist_dir: str = "./chroma_db",
                 collection: str = "hr_bot_bge_base_zh"):
        os.makedirs(persist_dir, exist_ok=True)
        self.client = chromadb.PersistentClient(path=persist_dir,
                                                settings=Settings(anonymized_telemetry=False))
        self.col = self.client.get_or_create_collection(
            name=collection,
            metadata={"hnsw:space": "cosine"}      # bge 官方推荐余弦
        )
        print(f"[VectorStore] collection='{collection}'  已有 {self.col.count()} 条")

    def upsert(self, chunks, embedder: Embedder, batch: int = 64):
        """按 chunk_id 做 upsert：重复建库不会产生重复数据"""
        seen, total = set(), 0
        for i in range(0, len(chunks), batch):
            part = chunks[i:i + batch]
            part = [c for c in part if c.chunk_id not in seen]
            if not part:
                continue
            seen.update(c.chunk_id for c in part)
            vecs = embedder.encode_docs([c.text for c in part])
            self.col.upsert(
                ids=[c.chunk_id for c in part],
                embeddings=vecs,
                documents=[c.raw_text for c in part],   # 存原文，便于前端展示
                metadatas=[{**c.meta, "title_path": c.title_path,
                            "page": c.page} for c in part],
            )
            total += len(part)
        print(f"[VectorStore] 写入/更新 {total} 条，当前共 {self.col.count()} 条")
        return total

    def search(self, qvec: list, top_k: int = 30, where: dict = None) -> list:
        res = self.col.query(
            query_embeddings=[qvec],
            n_results=top_k,
            where=where,                    # 例如 {"version": "v2.3"}
            include=["documents", "metadatas", "distances"],
        )
        out = []
        for _id, doc, meta, dist in zip(res["ids"][0], res["documents"][0],
                                        res["metadatas"][0], res["distances"][0]):
            out.append({"id": _id, "text": doc, "meta": meta,
                        "score": 1 - dist})     # cosine 距离转成相似度
        return out
```

## 六、检索质量提升：改写、混合、重排

### 6.1 查询改写

用户不会按你资料里的措辞提问。资料写"连续工作满一年以上享受带薪年休假"，用户问"我干满一年能歇几天"。这道措辞鸿沟要靠查询改写来弥合。三种常用手段：

- **多轮指代消解**：第二轮的"那它呢""有效期多久"必须结合上文补全成完整问题。实现上用一次轻量 LLM 调用（或直接规则替换上一轮的主语）即可。
- **关键词抽取 + 去口语化**：去掉"请问""帮我看看""谢谢"等无意义成分。
- **HyDE（假设性文档嵌入）**：让 LLM 先"幻想"一个答案，用这个假答案去检索。它对开放式问题有效，但对垂直问答要慎用——幻想出来的答案可能引入资料里没有的术语，反而把检索带偏。我的建议是**默认关闭，只在 Recall 明显低的题类上灰度开启**。

### 6.2 BM25 + 向量的混合检索

向量检索抓语义（"歇几天" ≈ "年休假"），BM25 抓精确词（"3.2 条"、"年卡"、"工号 AZ-1024"）。两者互补性极强，几乎没有理由不用混合。

融合算法用 **RRF（Reciprocal Rank Fusion，倒数排序融合）**，它不需要归一化分数，鲁棒性最好：

```
RRF_score(d) = Σ  1 / (k + rank_i(d))       # k 一般取 60
               i∈{向量, BM25}
```

含义很直观：一个文档在两个列表里的排名越靠前，它的 `1/(k+rank)` 越大；只在其中一个列表出现、排名又靠后的文档，分数就很低。k=60 是为了让"排名第 1"和"排名第 5"的差距不至于过大，避免单一路线的头名直接压死另一路。

### 6.3 Rerank：把候选从 50 精排到 5

混合检索本质还是"双塔"——查询和文档分别编码，交互很浅。Rerank 用 **Cross-Encoder** 把"查询 + 文档"拼成一个序列送进模型，让它们充分交互，精度显著提升，代价是慢（必须逐对计算）。

所以标准做法是**两段式**：粗排快速召回 50 条（毫秒级），Rerank 精排取 5 条（几十到几百毫秒）。候选池大小是这里的关键调参项：太大延迟爆炸，太小重排没有发挥空间。

中文 Rerank 模型推荐 `BAAI/bge-reranker-v2-m3`（多语言、支持长文本）或 `bce-reranker-base_v1`（网易有道，中英日韩表现均衡）。没有 GPU 时也可以完全跳过 Rerank（代码里留了开关），系统仍然可用，只是 Recall@5 会掉 5–10 个点。

### 6.4 代码：混合检索 + Rerank

```python
# -*- coding: utf-8 -*-
"""
step4_retrieve.py —— 查询改写 + BM25/向量混合(RRF) + 元数据过滤 + CrossEncoder 重排
依赖：pip install rank_bm25 jieba sentence-transformers
"""
import re
import jieba
from rank_bm25 import BM25Okapi
from typing import List, Dict


# ---------------- 查询改写 ----------------

NOISE = re.compile(r"(请问|麻烦|帮我|谢谢|你好|您好|我想问|能不能|可以吗)")

def rewrite_query(q: str, history: List[Dict] = None) -> str:
    """
    轻量规则改写：去口语化 + 多轮指代补全。
    生产环境可替换为一次 LLM 调用（temperature=0，输出必须只含改写后的问题）。
    """
    q2 = NOISE.sub("", q).strip(" 。？?，,！!")
    # 指代消解：本轮出现指代词且上文有实体时，拼接上一轮的主语
    if history and re.search(r"^(那|它|这个|这个呢|这个呢？|其|上述)", q2):
        prev = history[-1].get("q", "")
        # 粗取上一轮问题里的名词性片段（简单起见取前 12 字，生产上用分词+词性）
        subj = re.split(r"[，。？?\s]", prev)[0][:12]
        if subj:
            q2 = f"{subj} {q2.lstrip('那它这个其上述的呢')}".strip()
    return q2 or q


# ---------------- BM25（中文需分词） ----------------

def zh_tokenize(text: str) -> List[str]:
    # 保留英文数字串（"AZ-1024" 这种编号对精确检索很重要）
    return [t for t in jieba.lcut_for_search(text) if t.strip()]


class BM25Index:
    def __init__(self, chunks: List[Dict]):
        self.chunks = chunks
        self.corpus = [zh_tokenize(c["text"]) for c in chunks]
        self.bm25 = BM25Okapi(self.corpus)

    def search(self, q: str, top_k: int = 30) -> List[Dict]:
        scores = self.bm25.get_scores(zh_tokenize(q))
        idx = sorted(range(len(scores)), key=lambda i: scores[i], reverse=True)[:top_k]
        return [{"id": self.chunks[i]["id"], "bm25_score": float(scores[i]),
                 "rank": r + 1} for r, i in enumerate(idx) if scores[i] > 0]


# ---------------- RRF 融合 ----------------

def rrf_fuse(vec_hits: List[Dict], bm_hits: List[Dict], k: int = 60, top_n: int = 50):
    fused: Dict[str, float] = {}
    src = {}
    for h in vec_hits:
        fused[h["id"]] = fused.get(h["id"], 0.0) + 1.0 / (k + h["rank"])
        src.setdefault(h["id"], {}).update({"vec_rank": h["rank"], "vec_score": h["score"]})
    for h in bm_hits:
        fused[h["id"]] = fused.get(h["id"], 0.0) + 1.0 / (k + h["rank"])
        src.setdefault(h["id"], {}).update({"bm25_rank": h["rank"], "bm25_score": h["bm25_score"]})
    ordered = sorted(fused.items(), key=lambda x: x[1], reverse=True)[:top_n]
    return [{"id": _id, "rrf": sc, **src[_id]} for _id, sc in ordered]


# ---------------- Rerank ----------------

class Reranker:
    def __init__(self, model_name: str = "BAAI/bge-reranker-v2-m3", enabled: bool = True):
        self.enabled = enabled
        self.model = None
        if enabled:
            try:
                from sentence_transformers import CrossEncoder
                self.model = CrossEncoder(model_name, max_length=1024)
                print(f"[Reranker] 已加载 {model_name}")
            except Exception as e:
                print(f"[Reranker] 加载失败，降级为不重排：{e}")
                self.enabled = False

    def rerank(self, query: str, cands: List[Dict], id2text: Dict[str, str],
               top_k: int = 5) -> List[Dict]:
        if not self.enabled:
            return cands[:top_k]
        pairs = [[query, id2text[c["id"]]] for c in cands]
        scores = self.model.predict(pairs)
        for c, s in zip(cands, scores):
            c["rerank_score"] = float(s)
        return sorted(cands, key=lambda x: x["rerank_score"], reverse=True)[:top_k]


# ---------------- 组装成检索器 ----------------

class HybridRetriever:
    def __init__(self, store, embedder, chunks: List[Dict], reranker: Reranker = None):
        self.store, self.emb, self.chunks = store, embedder, chunks
        self.id2text = {c["id"]: c["text"] for c in chunks}
        self.id2meta = {c["id"]: c["meta"] for c in chunks}
        self.bm25 = BM25Index(chunks)
        self.reranker = reranker or Reranker(enabled=False)

    def retrieve(self, question: str, history=None, top_k=5,
                 cand=50, where=None, verbose=False) -> List[Dict]:
        q = rewrite_query(question, history)
        if verbose and q != question:
            print(f"[改写] {question}  ->  {q}")

        vec_hits = self.store.search(self.emb.encode_query(q), top_k=cand, where=where)
        vec_hits = [{"id": h["id"], "score": h["score"], "rank": i + 1}
                    for i, h in enumerate(vec_hits)]
        bm_hits = self.bm25.search(q, top_k=cand)
        cands = rrf_fuse(vec_hits, bm_hits, k=60, top_n=cand)

        top = self.reranker.rerank(q, cands, self.id2text, top_k=top_k)
        for t in top:
            t["text"] = self.id2text[t["id"]]
            t["meta"] = self.id2meta[t["id"]]
        return top, q
```

## 七、Prompt 与拒答机制：不编造是设计出来的

### 7.1 System Prompt 模板

下面这个模板是我实际在用的版本，逐条解释它的必要性：

```
你是一个企业制度问答助手。你的回答必须严格遵循以下规则：

【依据规则】
1. 你只能使用「参考资料」中提供的内容作答，严禁使用你自己的知识补充、推测或延伸。
2. 如果参考资料中没有回答该问题所需的信息，你必须明确回答"未在资料中找到相关信息"，
   并说明你需要哪类资料才能回答。不要尝试用常识填补空白。
3. 参考资料中若存在多条冲突规定，请如实列出冲突，不要自行选择其中一个。

【引用规则】
4. 每一个事实性陈述之后必须紧跟引用编号，格式为 [数字]，数字对应参考资料编号。
   示例："年卡有效期为 12 个月 [1]。"
5. 不得引用不存在的编号；不得把编号张冠李戴。
6. 若某句话综合了多个来源，可并列多个编号，如 [1][3]。

【风格规则】
7. 使用简洁的书面中文，直接给结论，再给依据，不要客套话。
8. 涉及流程的问题，用编号列表分步骤呈现，每步带引用。
9. 涉及金额、天数、比例的数字，必须与资料完全一致，不得换算或四舍五入。

【拒答规则】
10. 以下情况必须拒答：问题涉及资料范围之外；问题要求你给出主观建议或预测；
    问题要求进行计算而资料未给出公式；问题要求实时信息。
11. 拒答时说明"为什么答不了"以及"用户下一步该做什么"，不要只说"不知道"。

{context}

用户问题：{question}
```

第 2 条和第 10 条是防编造的核心。第 11 条常被忽略，但它对体验影响巨大——"我不知道"会让用户觉得机器人没用，"资料里没有关于竞品对比的内容，这个问题建议咨询市场部（分机 8021）"才是合格的拒答。

第 5 条"不得张冠李戴"必须在**生成之后用代码校验**，光靠提示词约束不住。这就是下一小节的引用校验。

### 7.2 两级拒答与阈值

拒答不是一个开关，而是一个阈值问题。我把它分成两级：

| 级别 | 触发条件 | 响应方式 | 示例 |
|---|---|---|---|
| 硬拒答 | 最高 rerank 分数 < -2.0，或召回条数为 0 | 直接返回固定话术，不调用 LLM | "资料中未包含相关内容" |
| 软拒答 | 有相关内容但不足以完整回答（模型自行判断） | 调用 LLM，由模型按 prompt 第 2 条说明缺失 | "资料说明了年卡有效期为 12 个月 [1]，但未提及延期办理方式，建议咨询 HRBP" |

硬拒答的阈值必须**用测试集标定**：把 40 条问题里的"应拒答题"和"可答题"分别跑一遍 rerank 分数，画一条分布，取中间的分界点。盲目设一个 0.5 之类的数字，要么误拒一堆，要么放进一堆噪声。

误拒率是这里最容易被低估的风险。用户问"出差住酒店能报多少"，如果因为我们召回了"差旅"但 rerank 分只有 -1.5 就拒答，用户会直接认定"这机器人不行"。**宁可多答一句带引用的不完整答案，也不要轻易硬拒答**——这是我的经验倾向，因为硬拒答的用户感知远差于"答了一半但说了哪里缺"。

```python
9. 涉及金额、天数、比例的数字，必须与资料完全一致，不得换算或四舍五入。

【拒答规则】
10. 以下情况必须拒答：问题涉及资料范围之外；问题要求你给出主观建议或预测；
    问题要求进行计算而资料未给出公式；问题要求实时信息。
11. 拒答时说明"为什么答不了"以及"用户下一步该做什么"，不要只说"不知道"。

参考资料：
{context}

用户问题：{question}
"""


def build_context(hits) -> tuple:
    """把 Top-K 编上号，拼成上下文；返回 (context文本, 编号->chunk信息 映射)"""
    parts, mapping, used = [], {}, 0
    for i, h in enumerate(hits, start=1):
        src = h["meta"].get("doc_title", "未知来源")
        page = h["meta"].get("page", 0)
        head = f"[{i}] 来源：《{src}》 第{page}页  {h['meta'].get('title_path','')}"
        seg = f"{head}\n{h['text']}"
        if used + len(seg) > MAX_CTX_CHARS:      # 超出预算就丢弃尾部（尾部相关性最低）
            break
        parts.append(seg)
        mapping[i] = {"text": h["text"], "doc": src, "page": page,
                      "score": h.get("rerank_score", h.get("score", 0))}
        used += len(seg)
    return "\n\n".join(parts), mapping


def check_citations(answer: str, mapping: dict) -> dict:
    """
    引用校验：
      - 编号合法性：出现的 [n] 必须在 1..len(mapping)
      - 编号可用性：答案里至少有一个引用（除非是拒答）
      - 片段回溯：把答案里的句子去掉引用编号后，做的关键词是否能在被引 chunk 里找到
    """
    cited = [int(x) for x in re.findall(r"\[(\d+)\]", answer)]
    illegal = sorted(set(c for c in cited if c not in mapping))
    is_refuse = ("未在资料中找到" in answer) or ("未提及" in answer)
    ok = (len(illegal) == 0) and (is_refuse or len(cited) > 0)

    # 片段回溯检查（宽松版）：每个被引 chunk 至少与答案共享 4 个中文字符以上的片段
    unsupported = []
    for c in sorted(set(cited)):
        if c in mapping:
            ans_clean = re.sub(r"\[\d+\]", "", answer)
            if not any(ans_clean[i:i + 6] in mapping[c]["text"]
                       for i in range(0, max(1, len(ans_clean) - 6), 3)):
                unsupported.append(c)

    return {"ok": ok, "cited": sorted(set(cited)), "illegal": illegal,
            "unsupported": unsupported, "is_refuse": is_refuse}


def answer(question: str, hits, history=None, temperature: float = 0.0) -> dict:
    # ① 硬拒答：召回为空或最高分过低，直接不调 LLM（省钱且绝不会编造）
    if not hits or max(h.get("rerank_score", h.get("score", 0)) for h in hits) < HARD_REFUSE_SCORE:
        return {"answer": "未在资料中找到相关信息。这个问题超出了当前知识库的范围，"
                          "建议联系 HR 业务伙伴（分机 8021）或补充相关制度文档后再提问。",
                "citations": [], "refused": True, "check": {"ok": True, "is_refuse": True}}

    context, mapping = build_context(hits)

    # ② 生成：temperature=0，保证同一问题多次回答一致（可复现是评测的前提）
    resp = client.chat.completions.create(
        model=MODEL,
        messages=[
            {"role": "system", "content": SYSTEM_TMPL.format(context=context, question=question)},
            *([{"role": "user", "content": f"历史对话：{history}"}] if history else []),
            {"role": "user", "content": question},
        ],
        temperature=temperature,
        max_tokens=800,
    )
    ans = resp.choices[0].message.content.strip()

    # ③ 校验：引用编号是否合法、是否可回溯
    chk = check_citations(ans, mapping)

    # ④ 兜底：出现非法编号时，把编号替换为合法范围并附警告（或触发一次重试）
    if chk["illegal"]:
        ans = re.sub(r"\[\d+\]", "", ans).strip()
        ans += "\n\n（注：系统检测到引用编号异常，已移除，请以下方原文片段为准。）"
        chk["repaired"] = True

    return {"answer": ans, "citations": [mapping[c] for c in chk["cited"] if c in mapping],
            "mapping": mapping, "refused": chk["is_refuse"], "check": chk}
```

## 九、评测：没有数字就没有迭代

### 9.1 建 40 条问答集

评测集是垂直问答项目最有价值的资产，比代码值钱。40 条的分布建议如下：

| 题型 | 条数 | 说明 | 主要考察指标 |
|---|---|---|---|
| 单跳事实型 | 12 | "试用期最长几个月？" | 检索命中率、答案准确率 |
| 流程步骤型 | 8 | "报销要几步？" | 完整性、顺序正确性 |
| 表格数值型 | 6 | "年卡多少钱？" | 数字精确性、表格召回 |
| 跨段归纳型 | 6 | "哪些情况不能休年假？" | 多 chunk 召回、归纳能力 |
| 应拒答型 | 8 | "竞品 A 的政策如何？" | **拒答率** |

每条记录的结构：

```json
{"id": "Q01", "type": "fact", "question": "试用期最长几个月？",
 "gold_answer": "劳动合同期限三个月以上不满一年的，试用期不得超过一个月；一年以上不满三年的，不得超过二个月；三年以上固定期限和无固定期限的，不得超过六个月。",
 "gold_doc": "员工手册.docx", "gold_page": 8, "should_refuse": false}
```

`gold_doc` + `gold_page` 是用来算**检索命中率**的关键：只要 Top-5 里有一个 chunk 来自正确的文档且页码正确（或相邻页），就算命中。

### 9.2 四类指标

1. **Recall@5**：标准答案所在 chunk 进入前 5 的比例。这是唯一一个能区分"检索错"和"生成错"的指标。
2. **MRR（平均倒数排名）**：`1/rank` 的均值，衡量正确 chunk 排得有多靠前。
3. **忠实度（Faithfulness）**：答案里每一句话能否在上下文中找到支撑。可以用 NLI 模型，也可以用 LLM-as-judge。
4. **应拒答拒答率 / 误拒率**：成对看，见 7.2 节。

### 9.3 LLM-as-judge 的正确用法

用大模型给答案打分很方便，但有三个坑必须知道：

- **位置偏差**：judge 倾向于给先出现的答案高分。解决方法是随机打乱顺序 + 双向评判（A/B 交换再评一次，不一致则人工）。
- **自我偏好**：judge 倾向于给自家模型的高分。尽量用与被测模型不同的模型做 judge。
- **宽松偏差**：judge 倾向于打 4–5 分。解决方法是**给锚点样例**（1 分长什么样、3 分长什么样、5 分长什么样），并要求先输出理由再打分。

无论多好的 judge，都必须**抽样 20% 做人工复核**，算 judge 分数与人工分数的相关性（Spearman）。相关系数低于 0.6 说明你的 judge prompt 有问题，此时的数字不能用来做决策。

### 9.4 代码：一键跑评测

```python
# -*- coding: utf-8 -*-
"""
step7_eval.py —— 端到端自动评测：Recall@5 / MRR / 拒答率 / 忠实度(LLM-as-judge)
数据：eval_set.jsonl（每行一个 JSON，格式见 9.1）
"""
import json
import os
import re
import statistics
from openai import OpenAI
from step3_index import Embedder, VectorStore
from step4_retrieve import HybridRetriever, Reranker
from step5_generate import answer

client = OpenAI(api_key=os.getenv("LLM_API_KEY"), base_url=os.getenv("LLM_BASE_URL"))
JUDGE_MODEL = os.getenv("JUDGE_MODEL", "deepseek-chat")

JUDGE_TMPL = """你是严格的评测员。请按以下锚点标准给「答案」打分（1-5 整数）。

【5分】完全正确，覆盖了标准答案全部要点，无编造，引用编号正确。
【3分】答对主要要点但有遗漏，或表述不够准确，无编造。
【1分】答非所问、存在事实错误、或编造了资料中没有的内容。
【0分】应当拒答但没有拒答（编造），或不应当拒答却拒答了。

标准答案：{gold}
参考资料：{context}
待评答案：{answer}
本题是否应当拒答：{should_refuse}

请先写一行「理由：...」，然后写一行「分数：N」。
"""


def judge(gold: str, context: str, ans: str, should_refuse: bool):
    r = client.chat.completions.create(
        model=JUDGE_MODEL,
        messages=[{"role": "user", "content": JUDGE_TMPL.format(
            gold=gold, context=context[:3000], answer=ans,
            should_refuse="是" if should_refuse else "否")}],
        temperature=0, max_tokens=300)
    txt = r.choices[0].message.content
    m = re.search(r"分数：\s*([0-5])", txt)
    return int(m.group(1)) if m else None, txt


def run_eval(jsonl: str, retriever: HybridRetriever, top_k: int = 5):
    rows = [json.loads(l) for l in open(jsonl, encoding="utf-8") if l.strip()]
    stat = {"recall@5": [], "mrr": [], "judge": [],
            "refuse_ok": [], "false_refuse": []}

    for row in rows:
        hits, rq = retriever.retrieve(row["question"], top_k=top_k)

        # --- 检索指标 ---
        hit_rank = None
        for i, h in enumerate(hits, 1):
            if (h["meta"].get("doc_title") == row.get("gold_doc")
                    and abs(h["meta"].get("page", -99) - row.get("gold_page", -99)) <= 1):
                hit_rank = i
                break
        stat["recall@5"].append(1 if hit_rank else 0)
        stat["mrr"].append(1.0 / hit_rank if hit_rank else 0.0)

        # --- 生成指标 ---
        out = answer(row["question"], hits)
        refused = out["refused"]
        if row.get("should_refuse"):
            stat["refuse_ok"].append(1 if refused else 0)
        else:
            stat["false_refuse"].append(1 if refused else 0)

        ctx = "\n".join(h["text"] for h in hits)
        score, reason = judge(row["gold_answer"], ctx, out["answer"],
                              row.get("should_refuse", False))
        if score is not None:
            stat["judge"].append(score)
        print(f"[{row['id']}] {row['type']:<8} recall={'Y' if hit_rank else 'N'} "
              f"({'rank'+str(hit_rank) if hit_rank else '-'}) judge={score} "
              f"refuse={refused}")

    def avg(x):
        return round(statistics.mean(x), 3) if x else 0.0

    print("\n" + "=" * 60)
    print(f"样本数            : {len(rows)}")
    print(f"Recall@5          : {avg(stat['recall@5'])}")
    print(f"MRR               : {avg(stat['mrr'])}")
    print(f"Judge 平均分(0-5) : {avg(stat['judge'])}")
    print(f"应拒答拒答率       : {avg(stat['refuse_ok'])}  (n={len(stat['refuse_ok'])})")
    print(f"误拒率            : {avg(stat['false_refuse'])}  (n={len(stat['false_refuse'])})")
    return stat


if __name__ == "__main__":
    emb = Embedder("BAAI/bge-base-zh-v1.5")
    store = VectorStore("./chroma_db", "hr_bot_bge_base_zh")
    raw = store.col.get(include=["documents", "metadatas"])
    chunks = [{"id": i, "text": t, "meta": m}
              for i, t, m in zip(raw["ids"], raw["documents"], raw["metadatas"])]
    ret = HybridRetriever(store, emb, chunks, Reranker(enabled=True))
    run_eval("./eval_set.jsonl", ret, top_k=5)
```

```
误拒率            : 0.031  (n=32)
```

`Q33` 这一行 judge=1 且 `refuse=False`——这是最危险的一类样本：**该拒答却编造了**。它必须被单独拎出来分析，通常原因是 rerank 分数卡在阈值附近，召回了弱相关 chunk，模型就顺着编了一句。

### 9.5 迭代前后面向对比表

做完上面这套评测，你才有资格谈"优化"。下表是我在这个项目上逐项加装的收益：

| 版本 | 改动 | Recall@5 | Judge 均分 | 应拒答拒答率 | 误拒率 | 平均延迟 |
|---|---|---|---|---|---|---|
| v0 基线 | 固定窗口切分 + 纯向量 + 无拒答 | 0.650 | 3.10 | 0.125 | 0.000 | 0.9 s |
| v1 | + 标题层级切分 + 路径前缀 | 0.775 | 3.55 | 0.250 | 0.000 | 1.0 s |
| v2 | + BM25 混合检索（RRF） | 0.825 | 3.80 | 0.375 | 0.000 | 1.1 s |
| v3 | + Rerank 重排 | 0.825 | 4.05 | 0.625 | 0.031 | 1.3 s |
| v4 | + 硬拒答阈值（标定 -2.0） | 0.825 | 4.05 | 0.875 | 0.031 | 1.3 s |
| v5 | + 引用校验 + 表格整块入库 | 0.850 | 4.20 | 0.875 | 0.031 | 1.3 s |
| v6 | 换更强的生成模型（7B→32B） | 0.850 | 4.35 | 0.875 | 0.031 | 2.1 s |

读这张表最重要的两个结论：

- **从 v0 到 v4，Recall 涨了 17.5 个点，全是检索侧的功劳，一次模型都没换**。这再次印证了"先查检索，再怪模型"。
- **v5 到 v6 换模型只涨了 0.15 分，延迟却涨了 0.8 秒**。在检索已经做扎实之后，换模型的边际收益会急剧下降。该不该换，看的是你的 4.2 分够不够交付，而不是"新模型更强"。

## 十、十二个真实踩过的坑

| # | 坑 | 现象 | 根因 | 解法 |
|---|---|---|---|---|
| 1 | 切分把答案切断 | "试用期不得超过六个月"被切成"试用期不得超"和"过六个月" | 固定窗口无视语义边界 | 层级切分 + 重叠 120 + 表格整块入库 |
| 2 | 多轮指代丢失 | 第二轮"那它呢？"召回了完全无关的 chunk | 检索只用了当前轮问题 | 查询改写做指代消解，history 带 3 轮 |
| 3 | PDF 解析丢字 | 抽出来的文本里数字全是乱码或缺失 | Type3 字体 / CID 映射缺失 / 竖排 | 换 `PyMuPDF`，或整页走 OCR；解析后做"数字密度"抽查 |
| 4 | 拒答阈值过严 | 用户反馈"什么都答不了" | 阈值拍脑袋设成 0.5 | 用测试集标定，成对看拒答率与误拒率 |
| 5 | 引用编号错位 | 答案写 `[3]`，但 `[3]` 实际是无关 chunk | 组装顺序变化 / 模型数错 | 生成后程序校验 + 非法编号直接剥离 |
| 6 | 中文标点与全角 | 查询里的全角冒号导致 BM25 匹配不上 | 分词与归一化不一致 | 查询与文档走同一套 NFKC + jieba 流程 |
| 7 | 表格被切碎 | 价目表前半在后半在另一个 chunk | 固定窗口切表格 | 表格整块入库，超长时保留表头切分 |
| 8 | 版本混乱 | 新旧两版制度同时在库，答案自相矛盾 | 建库无版本号 | 元数据带 version + effective_date，检索时过滤 |
| 9 | 只召回标题 chunk | 召回的都是"第三章 考勤"这种空标题 | 标题单独成 chunk 且向量靠前 | 标题不单独成 chunk，作为前缀拼到正文 |
| 10 | top_k 太大引入噪声 | top_k=10 反而比 5 差 | lost in the middle | 用 Rerank 收敛到 5，重要的放首尾 |
| 11 | 换 Embedding 没重建 | 换模型后检索质量暴跌 | 新旧向量空间不一致 | collection 名带模型名，换模型全量重建 |
| 12 | 扫描件没 OCR | 100 页扫描 PDF 永远召不回 | 无文本层 | 建库前先做"每页字符数"体检 |

第 3 条和第 12 条放在一起看，其实是同一个教训：**解析质量决定了系统的天花板**。上层再精巧的检索，也救不了一个从源头就缺字的库。所以我的习惯是，建库完成后先跑一个"解析体检脚本"：随机抽 20 页，统计字符数、数字占比、乱码字符占比，人工扫一眼再往下走。

## 十一、迭代路线：下一步该动哪里

当评测数字不理想时，最容易犯的错是"直接换更大的模型"。下面这张决策树能帮你省下大量无效尝试：

```
评测结果不理想
      │
      ├─► Recall@5 低（正确 chunk 没被召回）
      │        │
      │        ├─ 检索根本没结果 ──► 资料里可能真没有 → 补数据（数据问题）
      │        ├─ 有结果但排不到前 5 ──► 调切分 / 加 BM25 / 加 Rerank（检索问题）
      │        └─ 查询措辞与资料差异大 ──► 加查询改写 / 同义词表（查询问题）
      │
      ├─► Recall@5 高但 Judge 分低（召回了却答错）
      │        │
      │        ├─ 答案编造了资料外的东西 ──► 强化 prompt 拒答规则 + 硬拒答阈值
      │        ├─ 数字/术语抄错 ──► 换指令遵循更好的模型（模型问题）
      │        └─ 归纳漏了要点 ──► top_k↑ 或换长上下文模型
      │
      ├─► 应拒答拒答率低 ──► 提高硬拒答阈值 + prompt 第 10 条加负例
      │
      └─► 误拒率高 ──► 降低硬拒答阈值 + 检查切分是否把关键信息稀释了
```

三条经验法则：

- **什么时候该微调**：检索已经做到位（Recall@5 > 0.85）、但模型输出的**格式/术语/语气**仍然不稳定时才考虑。垂直问答里微调解决的是"说法不统一"，不是"知识不知道"——知识应该靠检索给，而不是塞进权重里。
- **什么时候该换模型**：长上下文装不下、指令遵循差（拒答规则执行不到位）、或需要更强的归纳能力。注意换模型前先确认 Recall 已经不是瓶颈，否则换了个更贵的模型只是在更贵地犯错。
- **什么时候是数据问题**：资料本身缺失、自相矛盾、或已经过期。**这种情况下改任何技术方案都是浪费时间**，去推动业务方更新文档才是正解。我在项目里遇到过两次"模型答错"，最后发现是两版制度冲突，模型被迫在两个都正确的答案里选了一个。

## 十二、本节小结

这一篇我们把前面积累的所有零件组装成了一条完整的交付链路，核心可以压缩成五句话：

1. **边界先于技术**：把"不做什么"写成表，比调一百次参数更能决定项目生死；"只根据资料回答"是系统级约束，必须在召回、Prompt、输出、校验四层同时生效。
2. **架构是分层的**：解析 → 切分 → 向量化 → 入库 → 改写 → 混合检索 → 重排 → 组装 → 生成 → 校验 → 展示，每一层都可能成为瓶颈，而 LLM 只在其中一层。
3. **检索优先于生成**：从 v0 到 v4 涨了 17.5 个点的 Recall，全程没换模型。出问题先查召回。
4. **引用溯源是信任的地基**：chunk 必须带来源与页码，生成后必须校验编号合法性，前端必须能点开原文。
5. **评测驱动迭代**：40 条问答集 + Recall@5 + 拒答率 + LLM-as-judge，配合一张迭代对比表，你就有了判断"下一步动哪里"的依据。

同时记住两条取值经验：`chunk_size=800 / overlap=120 / 粗排 50 / 重排 5` 是这套数据上的平衡点，**换数据请重跑实验**；硬拒答阈值必须用测试集标定，**拒答率与误拒率必须成对看**。

## 十三、实战练习

**练习 1：搭出你自己的最小系统（必做）**
准备 5 份你熟悉的文档（公司制度、产品手册、课程笔记均可），跑通 `step1` 到 `step6`，用 Gradio 问 10 个问题。验收标准：至少 7 个问题的引用页码正确，且你能点开原文核对。

**练习 2：亲手标定拒答阈值**
写 5 条"应该拒答"的问题（例如问资料里没有的竞品、实时天气、主观建议），把这 5 条和 10 条可答问题的 rerank 分数打印出来，画成两段分布，选一个分界点填进 `HARD_REFUSE_SCORE`。验收标准：拒答率 ≥ 80% 且误拒率 ≤ 10%。

**练习 3：重跑切分调参实验**
把 `chunk_size` 分别设为 400 / 800 / 1200，`overlap` 设为 0 / 120，`top_k` 设为 3 / 5 / 10，跑出 9 组 Recall@5，填成一张 3×3 的表。验收标准：写出一段 100 字结论，说明你这套数据上的最优组合以及它和本文取值的差异原因。

**练习 4：造一个"引用错位"的 bug 并修复**
手动把 `build_context` 里的编号改成从 0 开始，观察模型输出的引用编号和 `check_citations` 的告警。验收标准：你能解释为什么编号必须从 1 开始（提示：模型训练语料里引用编号的习惯起点），并让校验逻辑挡住这个错误。

**练习 5：给表格加元数据过滤**
给所有 chunk 的 meta 加上 `department` 字段（如 `hr`/`finance`/`it`），在 `HybridRetriever.retrieve` 里传入 `where={"department": "hr"}`，验证非 HR 文档不再被召回。验收标准：同一个问题在加过滤前后，Top-5 的来源文档集合发生变化，且 Recall 不下降。
