# 多头注意力与位置编码

**承上**：上一篇我们手推了 `softmax(QKᵀ/√d_k)V`，用 NumPy 跑出了"追"同时关注"猫"和"鼠"的权重矩阵。但那只是**单头**、且**没有位置信息**的注意力。

**本篇**：补上两块拼图——**多头注意力**（让模型同时拥有多种"关注视角"）和**位置编码**（告诉模型词的先后顺序）。这才是 Transformer 里真正在用的形态。

**启下**：有了这两件零件，下一篇《Transformer 架构——Encoder 与 Decoder 全解析》就能把它们和残差连接、LayerNorm、FFN 组装成完整的 Block，并从零搭出一个能跑的 mini Transformer。

**学完这一节，你能动手做**：

1. 用实验证明：不带位置编码的 Self-Attention 分不清词序（置换不变性）
2. 手写正弦位置编码，并验证"相对位置可由点积线性表达"这一性质
3. 从零实现 Multi-Head Attention，说清 reshape / transpose 的每一步维度变化

---

## 一、单头注意力的两个致命短板

### 短板 1：它是"词袋"，分不清先后顺序

Self-Attention 对输入做的是一个**集合（Set）运算**：它只看内容相似度，不看位置。如果你把句子里的词打乱顺序，输出只是**跟着换了行**，内容一模一样。

> "猫追老鼠" 和 "老鼠追猫" 在它眼里完全相同——这显然不行。

下面用代码把这个缺陷钉死（建议你亲手跑一遍，比读十遍论文都直观）。

### 短板 2：一个头只有一种"关注视角"

一个 token 和另一个 token 的关系是多维的：**句法上的主谓关系、语义上的同义关系、指代上的共指关系、位置上的邻近关系**……单头注意力只能学出**一种**加权模式，被迫把它们"平均"成一个。

类比 CNN：单头 = 只有一个卷积核，只能提一种特征；多头 = 一组卷积核，各自提取不同特征。

## 二、代码实战 1：证明置换不变性 + 手写正弦位置编码

```python
import numpy as np
np.random.seed(0)

def softmax(z):
    z = z - z.max(axis=-1, keepdims=True)   # 数值稳定
    e = np.exp(z)
    return e / e.sum(axis=-1, keepdims=True)

def attention(X, W):
    """最简单头自注意力：Q=K=V=X@W（便于演示置换不变性）"""
    Q = K = V = X @ W
    S = Q @ K.T / np.sqrt(W.shape[-1])
    return softmax(S) @ V

# ---------- 实验：打乱词序会发生什么 ----------
X = np.random.randn(5, 8)        # 5 个 token，每个 8 维
W = np.random.randn(8, 8)
out_orig = attention(X, W)

perm = [2, 0, 4, 1, 3]           # 打乱顺序
out_shuffled = attention(X[perm], W)

print("输出是否只是跟着换了行:", np.allclose(out_orig[perm], out_shuffled))
print("最大误差:", np.abs(out_orig[perm] - out_shuffled).max())
```

运行结果：

```
输出是否只是跟着换了行: True
最大误差: 8.88e-16
```

**结论**：误差是浮点精度级别的 0。不带位置编码的自注意力**完全丧失了顺序信息**——它就是一个"词袋模型"。所以位置编码不是锦上添花，而是**必需品**。

### 正弦位置编码

Transformer 原论文的方案：**不学习，直接算**。公式如下：

```
PE(pos, 2i)   = sin(pos / 10000^(2i/d_model))
PE(pos, 2i+1) = cos(pos / 10000^(2i/d_model))
```

- `pos`：token 在序列中的位置（0, 1, 2 …）
- `i`：维度下标（0, 1, 2 … d_model/2）
- 偶数维用 sin，奇数维用 cos

**为什么这样设计？** 不同维度对应不同的**波长**：`i` 小时频率高（能区分相邻位置），`i` 大时频率低（能把握长距离）。这本质上和二进制编码一样——低位变化快、高位变化慢，组合起来能唯一表示任意整数。

```python
def positional_encoding(max_len, d_model):
    pe = np.zeros((max_len, d_model))
    pos = np.arange(max_len)[:, None]                       # (max_len, 1)
    # 分母 10000^(2i/d_model)，取 log 形式避免上溢
    div = np.exp(np.arange(0, d_model, 2) * (-np.log(10000.0) / d_model))
    pe[:, 0::2] = np.sin(pos * div)      # 偶数维
    pe[:, 1::2] = np.cos(pos * div)      # 奇数维
    return pe

pe = positional_encoding(60, 64)

print("PE 前 4 个位置的前 6 维:")
print(np.round(pe[:4, :6], 3))
print("\n各位置向量范数:", np.round(np.linalg.norm(pe[:5], axis=1), 3))
```

运行结果：

```
PE 前 4 个位置的前 6 维:
[[ 0.     1.     0.     1.     0.     1.   ]
 [ 0.841  0.54   0.682  0.732  0.533  0.846]
 [ 0.909 -0.416  0.997  0.071  0.902  0.431]
 [ 0.141 -0.99   0.778 -0.628  0.993 -0.116]]

各位置向量范数: [5.657 5.657 5.657 5.657 5.657]
```

每个位置的编码向量范数都相同（= √(d_model/2) = √32 ≈ 5.657），这保证了**加上位置编码后不会改变原向量的尺度**，训练更稳定。

### 关键性质：相对位置可以被"线性"表达

正弦编码最漂亮的性质是：**对任意固定的相对距离 k，`PE(pos) · PE(pos+k)` 的值与绝对位置 pos 无关**。这意味着模型只要学会"点积大 = 距离近"，就能自动推广到没见过的位置。

```python
print("相对位置性质：PE(pos)·PE(pos+k) 是否只依赖 k")
for k in [1, 3, 10]:
    dots = [float(np.dot(pe[p], pe[p + k])) for p in range(20)]
    print(f"  k={k:2d}: 均值={np.mean(dots):7.3f}  标准差={np.std(dots):.3f}")
```

运行结果：

```
相对位置性质：PE(pos)·PE(pos+k) 是否只依赖 k
  k= 1: 均值= 30.917  标准差= 0.000
  k= 3: 均值= 25.587  标准差= 0.000
  k=10: 均值= 21.052  标准差= 0.000
```

**标准差是 0.000** ——无论 pos 是 0 还是 19，相距 k 的两个位置编码点积完全相同。而且 k 越大点积越小，天然编码了"距离衰减"。这就是正弦编码能**外推到比训练时更长的序列**的原因。

## 三、多头注意力（Multi-Head Attention）

### 核心思想

与其用 `d_model=768` 维做**一次**注意力，不如把它**切成 h=12 份**，每份 64 维，**各做一次**注意力，最后把 12 个结果拼回去：

```
d_model = 768, h = 12, d_head = 768 / 12 = 64

头1: 关注句法（主谓宾）
头2: 关注指代（"它"→前文的名词）
头3: 关注相邻词
...
头12: 关注标点与句子边界

concat → 线性投影 W_O → 输出
```

每个头有自己的 `W_Q^i, W_K^i, W_V^i`，因此可以**并行地捕捉不同类型的关系**。

### 维度变换全流程（最容易写错的地方）

设输入 `x: (batch, n, d_model)`：

```
1. 一次性投影（把 h 个头打包成一个大矩阵，效率更高）
   qkv = x @ W_qkv          W_qkv: (d_model, 3*d_model)
   q, k, v = chunk(qkv, 3)  各自 (batch, n, d_model)

2. 切头：把最后一维拆成 (h, d_head) 并把头提到第 1 维
   q.view(batch, n, h, d_head).transpose(1, 2)
   → (batch, h, n, d_head)     ← 这一步是灵魂：让每个头独立成"batch 维"

3. 各头并行算注意力（broadcast 自动生效）
   scores = q @ k.transpose(-2,-1) / √d_head     (batch, h, n, n)
   out    = softmax(scores) @ v                   (batch, h, n, d_head)

4. 拼回来
   out.transpose(1,2).contiguous().view(batch, n, d_model)

5. 输出投影
   y = out @ W_O              W_O: (d_model, d_model)
```

> ⚠️ **`.contiguous()` 不能漏**：`transpose` 只是改变了"读法"（stride），内存并不连续，直接 `view` 会报错。必须先 `contiguous()` 强制拷贝成连续内存，或者用 `.reshape()`（它会在需要时自动拷贝）。

### 参数量与计算量

多头注意力的参数量是 **4 · d_model²**（W_Q、W_K、W_V、W_O 各 d_model²），**与头数 h 无关**——因为每个头的维度被压缩成了 d_model/h。

这就是为什么"增加头数"几乎不增加参数量：总的计算量被重新分配，而不是增加。典型配置：

| 模型 | d_model | 头数 h | d_head | 层数 |
|---|---|---|---|---|
| BERT-base | 768 | 12 | 64 | 12 |
| BERT-large | 1024 | 16 | 64 | 24 |
| GPT-2 (1.5B) | 1600 | 25 | 64 | 48 |
| LLaMA-7B | 4096 | 32 | 128 | 32 |

你会发现 **`d_head` 基本固定在 64~128**——太小则每个头表达能力不足，太大则多头失去意义。

## 四、代码实战 2：从零实现 Multi-Head Attention

```python
import torch
import torch.nn as nn
import torch.nn.functional as F
import math

class MultiHeadAttention(nn.Module):
    def __init__(self, d_model: int, num_heads: int, dropout: float = 0.0):
        super().__init__()
        assert d_model % num_heads == 0, "d_model 必须能被 num_heads 整除"
        self.d_model = d_model
        self.h = num_heads
        self.d_head = d_model // num_heads

        # 三个投影打包成一个矩阵，一次乘法出 Q/K/V（工程上更快）
        self.W_qkv = nn.Linear(d_model, 3 * d_model)
        self.W_O = nn.Linear(d_model, d_model)
        self.dropout = nn.Dropout(dropout)

    def forward(self, x, causal: bool = False):
        batch, n, _ = x.shape
        h, d_head = self.h, self.d_head

        # 1) 投影并切成 Q/K/V
        qkv = self.W_qkv(x)                                   # (batch, n, 3*d_model)
        q, k, v = qkv.chunk(3, dim=-1)                        # 各 (batch, n, d_model)

        # 2) 拆头：(batch, n, d_model) -> (batch, h, n, d_head)
        q = q.view(batch, n, h, d_head).transpose(1, 2)
        k = k.view(batch, n, h, d_head).transpose(1, 2)
        v = v.view(batch, n, h, d_head).transpose(1, 2)

        # 3) 缩放点积注意力（各头并行）
        scores = q @ k.transpose(-2, -1) / math.sqrt(d_head)  # (batch, h, n, n)
        if causal:
            mask = torch.triu(torch.ones(n, n, dtype=torch.bool, device=x.device), 1)
            scores = scores.masked_fill(mask, float("-inf"))
        attn = F.softmax(scores, dim=-1)                      # (batch, h, n, n)
        attn = self.dropout(attn)
        out = attn @ v                                        # (batch, h, n, d_head)

        # 4) 拼回：(batch, h, n, d_head) -> (batch, n, d_model)
        out = out.transpose(1, 2).contiguous().view(batch, n, self.d_model)

        # 5) 输出投影
        return self.W_O(out), attn

# ---- 跑一遍并检查形状 ----
torch.manual_seed(42)
B, n, d_model, h = 2, 6, 32, 4
x = torch.randn(B, n, d_model)
mha = MultiHeadAttention(d_model, h)

y, attn = mha(x, causal=True)
print("输入形状:", x.shape)              # torch.Size([2, 6, 32])
print("输出形状:", y.shape)              # torch.Size([2, 6, 32])
print("注意力权重形状:", attn.shape)      # torch.Size([2, 4, 6, 6])  ← (batch, 头, 行, 列)

# 参数量统计
params = sum(p.numel() for p in mha.parameters())
print("参数量:", params, " 理论值 4*d_model^2 =", 4 * d_model ** 2)
```

输出：

```
输入形状: torch.Size([2, 6, 32])
输出形状: torch.Size([2, 6, 32])
注意力权重形状: torch.Size([2, 4, 6, 6])
参数量: 4096   理论值 4*d_model^2 = 4096
```

参数量与理论值完全一致，说明实现正确。注意力权重的形状 `(batch, h, n, n)` 正是可视化时最关心的那个张量——**你可以把每个头的 (n, n) 单独画成热力图，看看它到底在关注什么**。

### 加上位置编码，组装成完整输入

```python
class SinusoidalPositionalEncoding(nn.Module):
    def __init__(self, d_model: int, max_len: int = 5000):
        super().__init__()
        pe = torch.zeros(max_len, d_model)
        pos = torch.arange(max_len).unsqueeze(1).float()
        div = torch.exp(torch.arange(0, d_model, 2).float() * (-math.log(10000.0) / d_model))
        pe[:, 0::2] = torch.sin(pos * div)
        pe[:, 1::2] = torch.cos(pos * div)
        self.register_buffer("pe", pe.unsqueeze(0))    # (1, max_len, d_model)，不参与训练

    def forward(self, x):
        return x + self.pe[:, :x.size(1), :]           # 直接相加

# 验证：加了位置编码后，置换不变性被打破
pos_enc = SinusoidalPositionalEncoding(d_model)
y1, _ = mha(pos_enc(x), causal=True)
y2, _ = mha(pos_enc(x[:, [2, 0, 4, 1, 3, 5], :]), causal=True)
print("加位置编码后，输出是否还只是换行:", torch.allclose(y1[:, [2,0,4,1,3,5], :], y2))
# False  ← 顺序信息已经被注入
```

这就是"加性位置编码"：**直接加到 token 嵌入上**，简单有效。BERT 和早期 GPT 都这么做。

## 五、位置编码方案对比

| 方案 | 做法 | 代表模型 | 优点 | 缺点 |
|---|---|---|---|---|
| 正弦（Sinusoidal） | 固定公式，加到嵌入上 | 原始 Transformer | 无需训练、可外推到更长序列 | 表达力弱于可学习 |
| 可学习（Learned） | 当成参数表训练 | BERT、GPT-2 | 表达力强 | **不能外推**（训练多长就只能处理多长） |
| **RoPE（旋转）** | 对 Q/K 做复数旋转，用乘法注入 | **LLaMA、Qwen、ChatGLM、DeepSeek** | 天然表达相对位置、可外推（配合 NTK/PI 缩放） | 实现稍复杂 |
| ALiBi | 直接在注意力分数上减距离惩罚 | Bloom、MPT | 极简、外推性强 | 表达力有限 |

**现在的共识**：主流开源大模型（LLaMA 系列、Qwen 系列）几乎全部采用 **RoPE**。它的核心思想是——不把位置"加"进向量，而是对 Q 和 K 施加一个**与位置相关的旋转**，使得 `q_m · k_n` 的结果只依赖于**相对位置 m-n**：

```
RoPE:  q'_m = R(m)·q_m,   k'_n = R(n)·k_n
       q'_m · k'_n = f(q_m, k_n, m-n)     ← 只依赖相对距离
```

这比加性编码更优雅：位置信息直接作用在注意力分数上，而且天然满足"相对位置"这一语言本质需求。你在 HuggingFace 上看 Qwen 的 config，`rope_theta: 1000000.0` 就是这个旋转的基频。

## 六、常见坑

| 坑 | 现象 | 正确做法 |
|---|---|---|
| 忘了加位置编码 | 文本任务效果明显变差、词序不敏感 | 嵌入后必须加 PE |
| `view` 前忘了 `contiguous()` | RuntimeError: view size is not compatible | 先 `.contiguous()` 或用 `.reshape()` |
| 头数不能整除 d_model | assert 报错 | 选 64/128 之类能整除的配置 |
| 多头版本忘除以 √d_head | 注意力过尖锐、训练不稳 | 缩放因子是 **√d_head**，不是 √d_model |
| 位置编码长度不够 | 长文本直接报错 | `max_len` 要 ≥ 最大序列长度；或改用 RoPE/ALiBi |
| 把 PE 当可训练参数 | 无谓增加参数 | 用 `register_buffer`，它不参与梯度更新 |
| 因果 mask 在多头下失效 | 仍能看未来 | mask 形状要能 broadcast 到 (batch, h, n, n) |

## 七、本篇小结

1. **Self-Attention 是置换不变的**——我们用一个误差 8.88e-16 的实验证明了它分不清词序，所以位置编码是必需品。
2. **多头注意力**把 d_model 切成 h 份并行计算，让模型同时拥有多种关注视角；**参数量仍为 4·d_model²，与头数无关**。
3. 维度变换的灵魂是 `view(batch,n,h,d_head).transpose(1,2)`，把"头"提到第 1 维，让各头像 batch 一样并行。
4. **正弦位置编码**用不同频率的 sin/cos 编码绝对位置，且 `PE(pos)·PE(pos+k)` 只依赖 k（实测标准差 0.000），因此具备相对位置表达与外推能力。
5. 现代大模型主流改用 **RoPE 旋转位置编码**（Qwen / LLaMA / DeepSeek），直接用乘法把相对位置注入注意力分数。
