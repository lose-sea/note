# 预训练目标——MLM 与 CLM 到底在学什么

**承上**：上一篇我们说清了 BERT 用**掩码语言模型（MLM）**做填空、GPT 用**因果语言模型（CLM）**做续写，这个选择决定了它们的全部能力差异。

**本篇**：把这两种损失**手算一遍**，理解困惑度（perplexity）这个指标，并回答一个灵魂拷问——**"只是预测下一个词"这么简单的任务，凭什么能催生出推理能力？** 最后讲清"预训练 → 微调 → 对齐"三阶段。

**启下**：到这里，模型已经"会接话"了。但同一个模型，你用不同的问法会得到天差地别的结果。**阶段 6：提示词工程与大模型 API** 就是教你不改一个参数、只靠说话方式把它调教好的手艺。

**学完这一节，你能动手做**：

1. 手算交叉熵与困惑度，用数字判断一个语言模型到底好不好
2. 实现 loss masking（只对回答部分算损失），这是**指令微调的核心技巧**
3. 说清预训练 / SFT / 对齐三阶段各自解决什么问题，看懂一个模型的训练配方

## 一、CLM：预测下一个词

给定一串 token `x₁, x₂, ..., x_T`，CLM 的目标是最大化整个序列的联合概率。利用链式法则：

```
P(x₁, x₂, ..., x_T) = ∏ P(x_t | x₁, ..., x_{t-1})
                      t=1..T
```

取负对数，就得到要最小化的损失：

```
        1   T
L = - ───── Σ  log P(x_t | x_<t)
        T  t=1
```

**这就是交叉熵损失**，只是作用在"每个位置预测下一个词"这个任务上。注意它的特点：

- **每个位置都贡献损失**。序列长 2048，就有 2048 个监督信号。
- 数据是"自监督"的——**不需要任何人工标注**，互联网上的所有文本都是训练数据。

这就是大模型能吃到海量数据的根本原因：**标签就是文本本身**。

## 二、MLM：完形填空

BERT 的做法是随机盖住一部分词再让模型猜：

```
原句:   我 想 学 大 模 型
遮盖后: 我 [MASK] 学 大 [MASK] 型
目标:     想           模
```

**遮盖策略（15% 的三重分配）**，这是 BERT 论文里最容易被忽略却很关键的细节：

| 比例 | 处理 | 目的 |
|---|---|---|
| 15% 被选中 | — | 只有这些位置产生损失 |
| └ 其中 80% | 替换成 `[MASK]` | 主要学习信号 |
| └ 其中 10% | 替换成**随机词** | 迫使模型也关注"非掩码"位置的表示 |
| └ 其中 10% | **保持不变** | **缓解预训练/微调不一致**（微调时输入里没有 `[MASK]`） |

### MLM 的硬伤：训练信号稀疏

```
CLM:  序列 1000 个 token → 1000 个监督信号  ✅ 每个位置都在学
MLM:  序列 1000 个 token，遮盖 15% → 150 个监督信号  ❌ 少了 85%
```

同样的训练步数下，CLM 的学习效率显著更高。这是 Decoder-only 最终胜出的重要原因之一（另一个是生成任务的天然适配）。

## 三、代码实战 1：手算交叉熵与困惑度

困惑度（Perplexity, PPL）是语言模型最常用的指标，定义极其简单：

```
PPL = exp(交叉熵)
```

**直观含义**：模型在每个位置"相当于在 PPL 个词里犹豫不决"。PPL=1 表示完全确定（不现实），PPL=7 表示相当于在 7 个词里随机猜。

```python
import numpy as np

vocab = ["我", "想", "学", "大", "模", "型", "。"]
V = len(vocab)
w2i = {w: i for i, w in enumerate(vocab)}

# CLM 任务：输入 seq_in，每个位置要预测下一个词 seq_out
seq_out = ["想", "学", "大", "模", "型", "。"]
targets = np.array([w2i[w] for w in seq_out])

def make_probs(good):
    """构造一个"假模型"：它给正确词的概率是 good，剩余概率均分给其它词。"""
    P = np.full((len(seq_out), V), (1 - good) / (V - 1))
    for t, tgt in enumerate(targets):
        P[t, tgt] = good
    return P

def cross_entropy_and_ppl(P, targets):
    eps = 1e-12
    nll = -np.log(np.clip(P[np.arange(len(targets)), targets], eps, 1.0))
    ce = nll.mean()                 # 交叉熵
    return ce, np.exp(ce)           # 困惑度

for name, p in [("好模型 (80% 猜中)", 0.80),
                ("一般模型 (40%)",   0.40),
                ("随机模型 (1/7)",   1 / V)]:
    ce, ppl = cross_entropy_and_ppl(make_probs(p), targets)
    print(f"{name:20s} 交叉熵={ce:.4f}   困惑度={ppl:.3f}")
```

运行结果：

```
好模型 (80% 猜中)        交叉熵=0.2231   困惑度=1.250
一般模型 (40%)           交叉熵=0.9163   困惑度=2.500
随机模型 (1/7)           交叉熵=1.9459   困惑度=7.000
```

**怎么读**：

- 随机模型在 7 个词的词表里瞎猜，困惑度正好 = **7**（词汇表大小）。这是判断模型有没有在学的**基准线**：如果你的困惑度接近词表大小，说明模型什么都没学到。
- 好模型 80% 命中，困惑度只有 1.25——已经非常确定下一个词是什么。

**实用经验值**（中文/英文通用大模型，词表 10 万级）：

| 模型水平 | 困惑度范围 | 体感 |
|---|---|---|
| 优秀大模型 | 5 ~ 15 | 语句流畅、事实准确 |
| 可用 | 15 ~ 30 | 通顺，偶尔不通 |
| 较差 | 30 ~ 100 | 明显不流畅 |
| 没训出来 | ≈ 词表大小 | 完全乱码 |

> ⚠️ **困惑度不能直接跨词表比较**！词表大的模型（如 15 万）天然比词表小的（如 3 万）困惑度"看起来更高"，因为候选更多。比较时要在同一个 tokenizer 下算。

## 四、为什么"预测下一个词"能学会推理？

这是很多人第一次接触大模型时的疑惑。答案是：**这个任务看似简单，实则是一个无损压缩任务**。

要准确预测下一个词，模型必须隐式学会：

| 需要的能力 | 例子 |
|---|---|
| 语法 | "我 **想** 学" 而不是 "我想 **学** 了" |
| 世界知识 | "中国的首都是 ___" → 北京 |
| 逻辑推理 | "如果 A>B 且 B>C，那么 ___" → A>C |
| 代码结构 | 看到 `def foo():` 就知道后面要缩进 |
| 上下文连贯 | 论文里的符号、人物、论点要前后一致 |
| 意图推断 | "帮我写封辞职信" → 输出应该是信件 |

**"压缩即智能"**：要无损压缩海量文本，你必须理解文本背后的生成规律。预测下一个词，本质上就是在做这个压缩。

### Scaling Law：规模带来的可预测提升

研究者发现，模型性能（用 loss 衡量）与三个要素呈**幂律关系**：

```
Loss ∝ C^(-α)      C = 算力
Loss ∝ N^(-β)      N = 参数量
Loss ∝ D^(-γ)      D = 数据量
```

关键是：**这条曲线在几个数量级内都是平滑可预测的**。所以大家敢于砸钱——只要按规律扩大规模，loss 一定会降。这也解释了为什么"堆规模"在 2020-2024 年是有效的主旋律。

### 涌现能力（Emergent Abilities）

某些能力（少样本学习、链式推理、代码生成）不是平滑提升的，而是在规模跨过某个阈值后**突然出现**。典型的例子：GPT-3（175B）能做 few-shot 算术，而 13B 的版本怎么做都做不对。

> 学术界对"涌现"是否只是评测指标造成的假象仍有争论，但工程上的结论是明确的：**规模确实能带来质变**。

## 五、三阶段：预训练 → SFT → 对齐

一个能用的对话模型（比如 Qwen2.5-Instruct）不是一次性训出来的，而是三个阶段的产物：

```
① 预训练 Pre-training
   数据：海量无标注文本（TB 级）
   目标：CLM，学知识、学语言
   产物：基座模型（base）—— 只会续写，不会回答问题
              ↓
② 指令微调 SFT (Supervised Fine-Tuning)
   数据：人工/合成的"指令-回答"对（几万 ~ 几百万条）
   目标：CLM + loss masking，学会"按指令回答"
   产物：Instruct 模型 —— 听得懂人话
              ↓
③ 对齐 Alignment（RLHF / DPO / GRPO）
   数据：人类偏好标注（"回答 A 比 B 好"）
   目标：让输出符合人类价值观、有用、无害
   产物：Chat 模型 —— 好用且安全
```

| 阶段 | 数据量级 | 算力 | 你能自己做吗 |
|---|---|---|---|
| 预训练 | TB 级 | 千卡月 | ❌ 一般不自己做 |
| SFT | 万 ~ 百万条 | 单卡可行 | ✅ **阶段 9 会手把手做** |
| 对齐 | 万级偏好对 | 单卡 ~ 多卡 | ✅ 可用 DPO 简化 |

**作为开发者，你 99% 的场景是在第 ②③ 阶段做文章**——这也是本专栏阶段 9 的重点。

## 六、代码实战 2：loss masking（SFT 的核心技巧）

指令微调的数据长这样：

```
[提示词]  请把下面的句子翻译成英文：我想学大模型。
[回答]    I want to learn large language models.
```

**关键问题**：训练时，损失应该算在哪些 token 上？

- 算在**全部** token 上？→ 模型会花力气学"怎么生成用户的问题"，浪费算力，还可能让它学会胡编提示词。
- **正确做法**：只对**回答部分**计算损失，提示词部分的 label 设为 `-100`（PyTorch 的 `CrossEntropyLoss` 默认忽略这个值）。

```python
import numpy as np
np.random.seed(0)

def softmax(z):
    z = z - z.max(-1, keepdims=True)
    e = np.exp(z)
    return e / e.sum(-1, keepdims=True)

T, V = 6, 7                                     # 6 个位置，词表 7
logits = np.random.randn(T, V)                  # 模型输出（未归一化）
# 前 3 个位置是"回答"（要算 loss），后 3 个是"提示词"（被 mask 掉）
labels = np.array([2, 3, 4, -100, -100, -100])

P = softmax(logits)
mask = labels != -100                            # 等价于 PyTorch 的 ignore_index=-100

nll = -np.log(P[np.arange(T)[mask], labels[mask]])
print("只对回答部分算 loss:", round(float(nll.mean()), 4))
print("参与计算的位置数:", int(mask.sum()), "/", T)
```

运行结果：

```
只对回答部分算 loss: 2.2401
参与计算的位置数: 3 / 6
```

在实际代码里，PyTorch 一行就搞定：

```python
import torch.nn.functional as F

# prompt_len = 提示词部分的 token 数
labels = input_ids.clone()
labels[:, :prompt_len] = -100                    # 提示词部分不参与损失

loss = F.cross_entropy(
    logits[:, :-1, :].reshape(-1, vocab_size),   # 用第 t 个位置预测第 t+1 个
    labels[:, 1:].reshape(-1),                   # 目标右移一位
    ignore_index=-100
)
```

**三个必须注意的细节**：

1. **错位对齐**：第 `t` 个位置的输出预测的是第 `t+1` 个 token，所以 logits 取 `[:, :-1]`、labels 取 `[:, 1:]`。
2. **`ignore_index=-100`** 是 PyTorch 的约定，用别的值要显式传参。
3. **损失是"被 mask 后剩余位置"的平均**，不是总和——否则长回答的样本会压倒短回答。

## 七、常见坑

| 坑 | 现象 | 正确做法 |
|---|---|---|
| 困惑度跨词表比较 | 得出错误结论 | 必须在同一 tokenizer 下比 |
| loss 用了 sum 而非 mean | 长样本主导梯度 | `reduction='mean'`（默认值） |
| 忘了错位对齐 | loss 不下降 | logits 取前 n-1，labels 取后 n-1 |
| SFT 时把提示词也算 loss | 模型学歪、输出变短 | 提示词部分置 -100 |
| 拿 base 模型当 chat 用 | 它只会续写 | 下载 `-Instruct` / `-Chat` 版本 |
| 以为微调能注入大量新知识 | 效果差、灾难性遗忘 | 知识靠预训练/RAG；微调主要教**格式和风格** |

## 八、本篇小结

1. **CLM** 在每个位置都预测下一个词，**每个 token 都是监督信号**，效率高、与生成天然契合——这是 Decoder-only 胜出的关键。
2. **MLM** 只遮盖 15%，信号稀疏；它的 80/10/10 三重遮盖策略是为了缓解预训练与微调的不一致。
3. **困惑度 = exp(交叉熵)**，含义是"模型相当于在几个词里犹豫"。我们手算出：80% 命中 → PPL 1.25；随机 → PPL = 词表大小。**PPL 接近词表大小 = 模型没训出来**。
4. "预测下一个词"本质是**无损压缩任务**，被迫学会语法、知识、逻辑与意图——**压缩即智能**。
5. 现代对话模型 = **预训练 → SFT → 对齐** 三阶段产物，其中 loss masking（只对回答算损失）是 SFT 的核心工程技巧。
