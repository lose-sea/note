# 预训练目标——MLM 与 CLM 到底在学什么

**承上**：上一篇我们说清了 BERT 用**掩码语言模型（MLM）**做填空、GPT 用**因果语言模型（CLM）**做续写，这个选择决定了它们的全部能力差异。

**本篇**：把这两种损失**手算一遍**，理解困惑度（perplexity）这个指标，并回答一个灵魂拷问——**"只是预测下一个词"这么简单的任务，凭什么能催生出推理能力？** 最后讲清"预训练 → 微调 → 对齐"三阶段。

**启下**：到这里，模型已经"会接话"了。但同一个模型，你用不同的问法会得到天差地别的结果。**阶段 6：提示词工程与大模型 API** 就是教你不改一个参数、只靠说话方式把它调教好的手艺。

**学完这一节，你能动手做**：

1. 手算交叉熵与困惑度，用数字判断一个语言模型到底好不好
2. 实现 loss masking（只对回答部分算损失），这是**指令微调的核心技巧**
3. 说清预训练 / SFT / 对齐三阶段各自解决什么问题，看懂一个模型的训练配方

---

## 一、CLM：预测下一个词

给定一串 token `x₁, x₂, ..., x_T`，CLM 的目标是最大化整个序列的联合概率。利用链式法则：

```
P(x₁, x₂, ..., x_T) = ∏ P(x_t | x₁, ..., x_{t-1})
                      t=1..T
```

取负对数，就得到要最小化的损失：

```
        1   T
L = - ───── Σ  log P(x_t | x_<t)
        T  t=1
```

**这就是交叉熵损失**，只是作用在"每个位置预测下一个词"这个任务上。注意它的特点：

- **每个位置都贡献损失**。序列长 2048，就有 2048 个监督信号。
- 数据是"自监督"的——**不需要任何人工标注**，互联网上的所有文本都是训练数据。

这就是大模型能吃到海量数据的根本原因：**标签就是文本本身**。

### 1.1 "自监督"为什么是大模型的命门？

传统机器学习最大的成本瓶颈是**标注**：要教模型做情感分类，得先雇人标几万条"正面/负面"；要做翻译，得有双语对照语料。标注贵、慢、且覆盖不了长尾。

CLM 的天才之处在于**把"标签"免费生成了**：任何一段文本，把前 t-1 个词当输入、第 t 个词当标签，就自动构成一条训练样本。于是互联网上**所有能找到的文字——书籍、网页、代码、论文——都成了带标签的训练数据**，无需任何人工。这就是为什么 GPT 系列能在 TB 级无标注文本上训练：数据近乎无限、且零标注成本。这也是大模型区别于"小模型"的本质：**规模红利的前提，就是这种"不要钱"的自监督信号**。

### 1.2 为什么是"下一个词"而不是"上一个词"或"中间词"？

理论上，你也可以训练"预测上一个词"（反读文本）或"预测中间被盖住的词"（MLM）。为什么 CLM 选"下一个"成为主流？因为"下一个"天然对应**自回归生成**：模型学会了 P(下一个 | 之前)，就能从高到低一步步采样出完整文本，完美支撑对话、写作、代码生成。而"上一个词"的生成方向反了，"中间词"在推理时缺乏自回归的清爽结构。所以 CLM 不是偶然胜出，而是"训练目标"和"生成用途"在结构上严丝合缝——这又回到了本篇反复强调的"训练/推理一致性"铁律。

## 二、MLM：完形填空

BERT 的做法是随机盖住一部分词再让模型猜：

```
原句:   我 想 学 大 模 型
遮盖后: 我 [MASK] 学 大 [MASK] 型
目标:     想           模
```

**遮盖策略（15% 的三重分配）**，这是 BERT 论文里最容易被忽略却很关键的细节：

| 比例 | 处理 | 目的 |
|---|---|---|
| 15% 被选中 | — | 只有这些位置产生损失 |
| └ 其中 80% | 替换成 `[MASK]` | 主要学习信号 |
| └ 其中 10% | 替换成**随机词** | 迫使模型也关注"非掩码"位置的表示 |
| └ 其中 10% | **保持不变** | **缓解预训练/微调不一致**（微调时输入里没有 `[MASK]`） |

### MLM 的硬伤：训练信号稀疏

```
CLM:  序列 1000 个 token → 1000 个监督信号  ✅ 每个位置都在学
MLM:  序列 1000 个 token，遮盖 15% → 150 个监督信号  ❌ 少了 85%
```

同样的训练步数下，CLM 的学习效率显著更高。这是 Decoder-only 最终胜出的重要原因之一（另一个是生成任务的天然适配）。

### 2.1 那个"10% 保持不变"到底在缓解什么？

这是 BERT 设计里最精巧的一笔。训练时，80% 的被遮盖词变成 `[MASK]`——但**微调/推理时，真实输入里根本没有 `[MASK]` 这个符号**（比如做情感分类时，句子是完整的）。如果模型在预训练时只看 `[MASK]` 学会"填空"，到了下游任务面对"无 MASK 的真实句子"就会水土不服——这就是"预训练/微调不一致"。

BERT 的解法是：10% 的被遮盖词**保持原样不动**。于是模型在训练时被迫学会"即使这个词没被遮、看起来正常，也要根据上下文判断它是否合适/预测它的表示"。这等于在预训练阶段就提前模拟了"下游任务里没有 MASK"的分布，大幅减小了 train/serve 的分布偏移。一个小比例的设计，背后是"让训练分布贴近推理分布"的深刻工程直觉。

### 2.2 10% 替换成"随机词"又在防什么？

另一个 10% 故意把被盖的词换成**完全随机的词**。这看似"捣乱"，实则是为了让模型"别太依赖被遮位置本身"——如果 100% 都用 `[MASK]` 占位，模型可能学会一个偷懒策略："看到 `[MASK]` 就只看它附近，不去认真读整个句子的表示"。引入随机词后，模型发现"当前这个词可能是错的/无关的"，于是被迫**更关注全局上下文**来纠偏。两个 10% 共同保证了 BERT 学到的不是"局部填空技巧"，而是"真正的双向句子理解"。

## 三、代码实战 1：手算交叉熵与困惑度

困惑度（Perplexity, PPL）是语言模型最常用的指标，定义极其简单：

```
PPL = exp(交叉熵)
```

**直观含义**：模型在每个位置"相当于在 PPL 个词里犹豫不决"。PPL=1 表示完全确定（不现实），PPL=7 表示相当于在 7 个词里随机猜。

```python
import numpy as np

vocab = ["我", "想", "学", "大", "模", "型", "。"]
V = len(vocab)
w2i = {w: i for i, w in enumerate(vocab)}

# CLM 任务：输入 seq_in，每个位置要预测下一个词 seq_out
seq_out = ["想", "学", "大", "模", "型", "。"]
targets = np.array([w2i[w] for w in seq_out])

def make_probs(good):
    """构造一个"假模型"：它给正确词的概率是 good，剩余概率均分给其它词。"""
    P = np.full((len(seq_out), V), (1 - good) / (V - 1))
    for t, tgt in enumerate(targets):
        P[t, tgt] = good
    return P

def cross_entropy_and_ppl(P, targets):
    eps = 1e-12
    nll = -np.log(np.clip(P[np.arange(len(targets)), targets], eps, 1.0))
    ce = nll.mean()                 # 交叉熵
    return ce, np.exp(ce)           # 困惑度

for name, p in [("好模型 (80% 猜中)", 0.80),
                ("一般模型 (40%)",   0.40),
                ("随机模型 (1/7)",   1 / V)]:
    ce, ppl = cross_entropy_and_ppl(make_probs(p), targets)
    print(f"{name:20s} 交叉熵={ce:.4f}   困惑度={ppl:.3f}")
```

运行结果：

```
好模型 (80% 猜中)        交叉熵=0.2231   困惑度=1.250
一般模型 (40%)           交叉熵=0.9163   困惑度=2.500
随机模型 (1/7)           交叉熵=1.9459   困惑度=7.000
```

**怎么读**：

- 随机模型在 7 个词的词表里瞎猜，困惑度正好 = **7**（词汇表大小）。这是判断模型有没有在学的**基准线**：如果你的困惑度接近词表大小，说明模型什么都没学到。
- 好模型 80% 命中，困惑度只有 1.25——已经非常确定下一个词是什么。

**实用经验值**（中文/英文通用大模型，词表 10 万级）：

| 模型水平 | 困惑度范围 | 体感 |
|---|---|---|
| 优秀大模型 | 5 ~ 15 | 语句流畅、事实准确 |
| 可用 | 15 ~ 30 | 通顺，偶尔不通 |
| 较差 | 30 ~ 100 | 明显不流畅 |
| 没训出来 | ≈ 词表大小 | 完全乱码 |

> ⚠️ **困惑度不能直接跨词表比较**！词表大的模型（如 15 万）天然比词表小的（如 3 万）困惑度"看起来更高"，因为候选更多。比较时要在同一个 tokenizer 下算。

### 3.1 困惑度的"等效选择数"直觉怎么用？

记住一句话：**困惑度 PPL ≈ 模型在每个位置"要在多少个等概率候选里挑"**。PPL=7，相当于"7 选 1"；PPL=50，相当于"50 选 1"。所以：

- 衡量"模型变好没变好"：看 PPL 是否下降。哪怕从 50 降到 40，也是实打实的提升（相当于从 50 选 1 变成 40 选 1，确定性提高）。
- 比较不同模型：必须**同词表、同测试集**，否则数字没有可比性。很多人拿"GPT-4 的 PPL"和"某小模型的 PPL"直接比，是无效比较——词表、测试语料都不一样。

### 3.2 困惑度的局限：它不等于"能力强"

PPL 只衡量"预测下一个词的确定性"，但**不等于"有用、正确、安全"**。一个模型可能 PPL 很低（文本很通顺），却经常胡说八道（hallucination）；另一个 PPL 稍高，却更诚实、更少编造。所以：

- PPL 适合做**训练过程中的监控指标**（看 loss 是否收敛、是否过拟合）；
- 模型"好不好用"要靠**下游任务评测**（MMLU、HumanEval、真实业务准确率）和对齐程度来判断。

这也是为什么业界不单看 PPL，而要建立多维评测体系。你做模型微调时，PPL 是"健康度体温计"，但别把它当"能力成绩单"。

## 四、为什么"预测下一个词"能学会推理？

这是很多人第一次接触大模型时的疑惑。答案是：**这个任务看似简单，实则是一个无损压缩任务**。

要准确预测下一个词，模型必须隐式学会：

| 需要的能力 | 例子 |
|---|---|
| 语法 | "我 **想** 学" 而不是 "我想 **学** 了" |
| 世界知识 | "中国的首都是 ___" → 北京 |
| 逻辑推理 | "如果 A>B 且 B>C，那么 ___" → A>C |
| 代码结构 | 看到 `def foo():` 就知道后面要缩进 |
| 上下文连贯 | 论文里的符号、人物、论点要前后一致 |
| 意图推断 | "帮我写封辞职信" → 输出应该是信件 |

**"压缩即智能"**：要无损压缩海量文本，你必须理解文本背后的生成规律。预测下一个词，本质上就是在做这个压缩。

### 4.1 "压缩即智能"（Compression ≈ Intelligence）再深挖

这个说法来自信息论：一个能完美预测数据的模型，等价于一个能完美压缩数据的模型（预测概率 = 压缩率）。而"压缩"需要"理解结构"——你无法压缩一段你不懂规律的数据。所以一个把人类文本压缩得极好的模型，必然已经"理解"了语言中的语法、事实、逻辑。

这给了我们一个很强的能力上限直觉：**模型不是"背下了答案"，而是"学到了生成答案的规律"**。所以它能泛化到没见过的组合（比如你问一个全新的推理题，它也能答），因为它用的是学到的"规律"而非"记忆的模板"。当然，这也意味着它会在"规律边界外"犯错（编造看似合理但错误的内容）——理解这一点，你就不会神话大模型，也不会低估它。

### 4.2 为什么"预测下一个词"能涌现出推理，而不是只会"接话"？

关键在"预测的每一步都依赖前面的推理"。要预测"所以 ___"，模型必须先"理解前文已经推导到哪一步"，才能接出正确结论。换句话说，**推理是"正确预测下一个词"的必要前提**——你不能在不做推理的情况下，稳定地预测出逻辑链条的下一环。于是训练目标"被迫"让模型内化了一套推理能力，而不只是表层统计。

这就是所谓的" emergent reasoning（涌现推理）"：它并非被显式编程，而是"为了把下一个词预测准"这个单一目标，在数学上必然要求模型发展的副产品。理解这点，你对"大模型为什么会推理"就不再神秘，而是把它看作优化目标的自然结果。

### Scaling Law：规模带来的可预测提升

研究者发现，模型性能（用 loss 衡量）与三个要素呈**幂律关系**：

```
Loss ∝ C^(-α)      C = 算力
Loss ∝ N^(-β)      N = 参数量
Loss ∝ D^(-γ)      D = 数据量
```

关键是：**这条曲线在几个数量级内都是平滑可预测的**。所以大家敢于砸钱——只要按规律扩大规模，loss 一定会降。这也解释了为什么"堆规模"在 2020-2024 年是有效的主旋律。

> 注意：Scaling Law 是"经验规律"而非"物理定律"。它在当前架构（Transformer + CLM）下高度成立，但未来架构变化可能改变斜率。它告诉我们"加大投入大概率有效"，但不保证"无限加大就一定无敌"。

### 涌现能力（Emergent Abilities）

某些能力（少样本学习、链式推理、代码生成）不是平滑提升的，而是在规模跨过某个阈值后**突然出现**。典型的例子：GPT-3（175B）能做 few-shot 算术，而 13B 的版本怎么做都做不对。

> 学术界对"涌现"是否只是评测指标造成的假象仍有争论，但工程上的结论是明确的：**规模确实能带来质变**。

### 4.3 给开发者的实用启示：别和 Scaling Law 对着干

理解了规模律，你做应用时有几条铁律：

1. **小模型做不了的事，别硬调 prompt**：如果 7B 模型反复算错小学数学，先考虑换更大模型，而不是花一周雕 prompt——能力是规模给的，prompt 只是"唤起"能力。
2. **数据质量 > 数据数量**：Scaling Law 里的 D 是"有效数据量"，脏数据、重复数据会稀释效果。所以清洗语料（去重、过滤低质）比堆量更重要。
3. **但 prompt/对齐能放大已有能力**：大模型"会但未必乖"，好的提示词和 SFT 能让它"把会的东西用出来"。所以"规模打底 + 工程唤醒"是标准打法。

## 五、三阶段：预训练 → SFT → 对齐

一个能用的对话模型（比如 Qwen2.5-Instruct）不是一次性训出来的，而是三个阶段的产物：

```
① 预训练 Pre-training
   数据：海量无标注文本（TB 级）
   目标：CLM，学知识、学语言
   产物：基座模型（base）—— 只会续写，不会回答问题
              ↓
② 指令微调 SFT (Supervised Fine-Tuning)
   数据：人工/合成的"指令-回答"对（几万 ~ 几百万条）
   目标：CLM + loss masking，学会"按指令回答"
   产物：Instruct 模型 —— 听得懂人话
              ↓
③ 对齐 Alignment（RLHF / DPO / GRPO）
   数据：人类偏好标注（"回答 A 比 B 好"）
   目标：让输出符合人类价值观、有用、无害
   产物：Chat 模型 —— 好用且安全
```

| 阶段 | 数据量级 | 算力 | 你能自己做吗 |
|---|---|---|---|
| 预训练 | TB 级 | 千卡月 | ❌ 一般不自己做 |
| SFT | 万 ~ 百万条 | 单卡可行 | ✅ **阶段 9 会手把手做** |
| 对齐 | 万级偏好对 | 单卡 ~ 多卡 | ✅ 可用 DPO 简化 |

**作为开发者，你 99% 的场景是在第 ②③ 阶段做文章**——这也是本专栏阶段 9 的重点。

### 5.1 为什么必须分三个阶段，不能一步到位？

有人会问：既然对齐后的模型最好用，为什么不直接从零训练一个"既懂知识又懂对齐"的模型？原因是**三件事难度和成本天差地别**：

- **预训练**要吞 TB 级数据、烧千卡月的算力，才能把"世界知识"塞进参数。这是资本密集型工程，个人/小团队做不了。
- **SFT** 只需几万到几百万条"指令-回答"，单卡就能跑，目的是把"已具备的知识"对齐到"人类想要的回答格式"。
- **对齐**只需万级偏好数据，用 DPO 这种"无需训练奖励模型"的方法，单卡也能做。

把"学知识"和"学规矩"解耦，意味着**你不必重训模型就能调教它的行为**——这正是 LoRA、DPO 这类"轻量微调"技术流行的根本原因。理解三阶段的分工，你就明白"作为应用开发者，你的主战场在 ②③"这句话的分量。

### 5.2 一个常见误解："微调能注入大量新知识"

很多人以为微调（SFT）是"教模型新知识"的手段。实际上，SFT 主要教的是**格式、风格、指令遵循**——让模型学会"按这种结构回答"。真正的事实性知识，99% 来自预训练阶段。

后果是：

- 想让模型"知道"某个新领域知识，光靠几条 SFT 样本几乎无效，正确做法是**RAG（检索增强）把知识喂进上下文**，或**做领域预训练/继续预训练**（成本高）；
- SFT 样本如果和模型已有知识冲突，反而容易造成"灾难性遗忘"或胡编。

所以口诀是：**知识靠预训练/RAG，能力靠 SFT，偏好靠对齐**。别指望微调给模型"补常识"。

### 5.3 你作为应用开发者，到底要"训练"什么？

把三阶段映射到你的日常工作，会很清晰：

- **预训练**：你基本不碰（除非你在做大厂基础模型团队）。这是"造地基"的活。
- **SFT**：你最常做。比如把自己的客服话术、产品知识、输出格式整理成"指令-回答"对，微调出一个"懂你业务语气"的模型。数据量几千到几万条就够起步。
- **对齐**：你需要但不一定自己训奖励模型。用 **DPO** 这种"直接拿偏好对优化"的方法，几千条"A 比 B 好"的数据就能让模型变礼貌、变安全、变听话，单卡即可。

所以"你 99% 的精力在 ②③ 阶段"这句话，落到行动上就是：**学会做 SFT 数据 + 学会用 DPO/LoRA 做轻量微调**。这是本专栏阶段 9 的核心交付能力，也是"从会用模型到能定制模型"的分水岭。

## 六、代码实战 2：loss masking（SFT 的核心技巧）

指令微调的数据长这样：

```
[提示词]  请把下面的句子翻译成英文：我想学大模型。
[回答]    I want to learn large language models.
```

**关键问题**：训练时，损失应该算在哪些 token 上？

- 算在**全部** token 上？→ 模型会花力气学"怎么生成用户的问题"，浪费算力，还可能让它学会胡编提示词。
- **正确做法**：只对**回答部分**计算损失，提示词部分的 label 设为 `-100`（PyTorch 的 `CrossEntropyLoss` 默认忽略这个值）。

```python
import numpy as np
np.random.seed(0)

def softmax(z):
    z = z - z.max(-1, keepdims=True)
    e = np.exp(z)
    return e / e.sum(-1, keepdims=True)

T, V = 6, 7                                     # 6 个位置，词表 7
logits = np.random.randn(T, V)                  # 模型输出（未归一化）
# 前 3 个位置是"回答"（要算 loss），后 3 个是"提示词"（被 mask 掉）
labels = np.array([2, 3, 4, -100, -100, -100])

P = softmax(logits)
mask = labels != -100                            # 等价于 PyTorch 的 ignore_index=-100

nll = -np.log(P[np.arange(T)[mask], labels[mask]])
print("只对回答部分算 loss:", round(float(nll.mean()), 4))
print("参与计算的位置数:", int(mask.sum()), "/", T)
```

运行结果：

```
只对回答部分算 loss: 2.2401
参与计算的位置数: 3 / 6
```

在实际代码里，PyTorch 一行就搞定：

```python
import torch.nn.functional as F

# prompt_len = 提示词部分的 token 数
labels = input_ids.clone()
labels[:, :prompt_len] = -100                    # 提示词部分不参与损失

loss = F.cross_entropy(
    logits[:, :-1, :].reshape(-1, vocab_size),   # 用第 t 个位置预测第 t+1 个
    labels[:, 1:].reshape(-1),                   # 目标右移一位
    ignore_index=-100
)
```

**三个必须注意的细节**：

1. **错位对齐**：第 `t` 个位置的输出预测的是第 `t+1` 个 token，所以 logits 取 `[:, :-1]`、labels 取 `[:, 1:]`。
2. **`ignore_index=-100`** 是 PyTorch 的约定，用别的值要显式传参。
3. **损失是"被 mask 后剩余位置"的平均**，不是总和——否则长回答的样本会压倒短回答。

### 6.1 为什么"提示词也算 loss"会害了模型？

如果 loss 把用户提问也算进去，模型在训练时会努力"模仿如何生成用户的问题"。这带来两个坏处：

1. **算力浪费**：模型本该把表征容量花在"怎么答好"上，却分心去学"怎么把问题复述一遍"；
2. **行为漂移**：推理时用户会自己输入问题，模型若在 prompt 上也产生梯度，容易学会"自问自答、抢在用户前把问题造出来"的坏习惯（所谓"prompt injection 式"的复读）。

所以 masking 不只是"省算力"，更是**明确告诉模型：你只对被问之后的回答负责**。这是 SFT 质量的命门，几乎所有开源微调框架（LLaMA-Factory、Axolotl）都默认对 prompt 做 -100 屏蔽。

### 6.2 不止 prompt masking：SFT 里还有哪些"标签工程"？

- **多轮对话 masking**：在 chat 数据中，通常只对"助手"轮次的 token 算 loss，用户轮次和 system 轮次全设 -100（HF 的 `DataCollatorForLanguageModeling` / 各 SFT 脚本都这么做）。
- **工具调用 / 思考链 masking**：如果训练"先思考后回答"的数据，有时只对"最终答案"算 loss、对"思考过程"屏蔽，或反之——取决于你想让模型学会哪部分。
- **序列打包（packing）**：把多条短样本拼成一条长序列以提升吞吐，此时**样本边界也要 mask**，避免模型"跨样本偷看/预测"，否则会污染训练信号。

一句话：**SFT 的精髓往往不在"模型结构"，而在"你怎么构造 labels"**。把 mask 用对，小数据也能调教出听话的模型。

## 七、常见坑

| 坑 | 现象 | 正确做法 |
|---|---|---|
| 困惑度跨词表比较 | 得出错误结论 | 必须在同一 tokenizer 下比 |
| loss 用了 sum 而非 mean | 长样本主导梯度 | `reduction='mean'`（默认值） |
| 忘了错位对齐 | loss 不下降 | logits 取前 n-1，labels 取后 n-1 |
| SFT 时把提示词也算 loss | 模型学歪、输出变短 | 提示词部分置 -100 |
| 拿 base 模型当 chat 用 | 它只会续写 | 下载 `-Instruct` / `-Chat` 版本 |
| 以为微调能注入大量新知识 | 效果差、灾难性遗忘 | 知识靠预训练/RAG；微调主要教**格式和风格** |

### 7.1 进阶坑：训练不稳定时的排查清单

- **loss 一开始就是 ln(V) 且不动**：检查数据标签是否错位（是否忘了 `labels[:, 1:]`）、学习率是否过低、初始化是否异常。
- **loss 突然变 nan**：多半是 fp16 下 softmax/注意力溢出，换成 bf16，或检查输入是否有全 padding 的行导致 softmax 除 0。
- **过拟合快**：SFT 数据少时模型几步就"背下"样本、泛化差，用更小的学习率（如 1e-5~2e-5）、加 LoRA 而非全量微调、或扩充数据。
- **生成变短/复读**：检查是否 prompt 部分没 mask，或 SFT 数据里"回答"占比过低。

## 八、本篇小结

1. **CLM** 在每个位置都预测下一个词，**每个 token 都是监督信号**，效率高、与生成天然契合——这是 Decoder-only 胜出的关键。
2. **MLM** 只遮盖 15%，信号稀疏；它的 80/10/10 三重遮盖策略是为了缓解预训练与微调的不一致。
3. **困惑度 = exp(交叉熵)**，含义是"模型相当于在几个词里犹豫"。我们手算出：80% 命中 → PPL 1.25；随机 → PPL = 词表大小。**PPL 接近词表大小 = 模型没训出来**。
4. "预测下一个词"本质是**无损压缩任务**，被迫学会语法、知识、逻辑与意图——**压缩即智能**。
5. 现代对话模型 = **预训练 → SFT → 对齐** 三阶段产物，其中 loss masking（只对回答算损失）是 SFT 的核心工程技巧。
6. **阶段 5 完结**：你已经能读懂 Transformer 论文、看懂 HuggingFace 源码、估算模型规模与成本。
