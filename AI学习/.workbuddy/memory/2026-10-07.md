## 修复仓库在 Windows 上无法拉取（invalid path）

- **现象**：Windows 上 GitHub Desktop 拉取 `lose-sea/note` 报
  `error: invalid path 'AI学习/ai-daily/函数——参数、lambda、*args与作用域.md' Merge with strategy ort failed.`
- **根因**：该文件名含 `*`，属于 Windows 非法字符（`< > : " \ | ? *`）。
- **审计结论**：全仓库 540 个受控文件，**仅这 1 个** 违反 Windows 命名规则；
  另查无大小写不敏感冲突（0 组）、无超长路径（>150 字符 0 个）、无 Windows 保留名（CON/PRN/COM1…）、无结尾空格/点。
- **修复**：按用户选择，用 `git mv` 改为全角星号 →
  `AI学习/ai-daily/函数——参数、lambda、＊args与作用域.md`（U+FF0A，Windows 合法）。
  提交 `a0bc5c1 fix: 重命名含 * 的笔记文件为全角＊，修复 Windows 无法拉取 (invalid path)`，纯改名（0 增删），已推送。
- **未做历史重写**：用户选择「只加一次改名提交」，旧提交中的 `*` 路径仍存在于历史里，
  因此**新克隆/检出新 HEAD 正常**，但 checkout 到 a0bc5c1 之前的旧提交仍会失败。
- **仓库根目录提醒**：`git rev-parse --show-toplevel` = `/Users/lose_sea/Documents/github/note`，
  `AI学习` 只是其中一个子目录（同级还有 3G、C_learning、python_learning、日报周报 等）。
- **审计/排查要点**：`git ls-files` 默认 `core.quotepath=true` 会把中文转义成八进制、并给含空格/特殊字符的路径加引号，
  直接用管道 grep 会误判（曾误报 531 个文件含 `"` 和 `\`）。正确做法：用 `git ls-files -z`，
  或 `git -c core.quotepath=false ls-tree`。
- 用户 Windows 端未提交的 `requirement.txt`、`从0开始构建一个R..._test.py` **不在本仓库**（未跟踪），`git reset --hard` 不会影响它们。
